# Структура `docs/` и жизненный цикл документов

Семь папок, ничего больше. Файлов в корне `docs/` не держим — только `README.md`.

| Папка | Что лежит | Живёт |
|---|---|---|
| `active/` | документ задачи, которая идёт прямо сейчас | до завершения задачи |
| `archive/` | завершённые задачи, планы, отчёты — плоско, `<slug>-<YYYY-MM-DD>.md` | навсегда, не читается по умолчанию |
| `decisions/` | ADR: почему выбрано так, а не иначе | навсегда |
| `solutions/` | переиспользуемое решение проблемы + `INDEX.md` | навсегда |
| `reference/` | долгоживущие справочники (security, guidelines, маркетинг, healthcheck) | навсегда |
| `todos/` | отложено **внешней** блокировкой + `done/` + `INDEX.md` | до наступления триггера |
| `backlog/` | «сделаем когда-нибудь» + `INDEX.md` | до взятия в работу |

Новую папку верхнего уровня не заводить. Не подходит ни одна — значит документ либо `archive/`, либо `reference/`.

## Жизненный цикл документа задачи

`active/<slug>-<date>.md` → задача закрыта → `**Статус:** Done` в шапке → **файл переезжает в `archive/`**. `active/` содержит только незавершённое.

Статус в шапке — ровно одно значение из словаря: `In Progress` | `Done` | `Deferred` | `Planned` | `Partially Done`. Формат строго `**Статус:** <значение>` — без буллета, эмодзи и хвостов в той же строке (иначе SessionStart-дайджест парсит мимо шапки). Промежуточные отметки в `## Лог итераций` пишутся как `**Итог итерации:**`, не `**Статус:**`.

Задача фактически завершена, но `/task-gate` и `@doc-writer` не отработали (сессия оборвалась, документ создавали вручную) — статус и перенос делает главный агент сам. Завершённое не оставлять в `active/` как `In Progress`.

## Документация едет в том же merge request, что и код

Документ, написанный по ходу задачи, обязан попасть в тот же коммит и MR, что и код этой задачи. Иначе ветка уезжает без документации, а документ остаётся в рабочем дереве и устаревает раньше, чем его кто-то увидит.

Субагенты git не трогают — стейджит и коммитит главный. Чтобы ему было что стейджить, `@doc-writer` возвращает строку `DOCS_WRITTEN:` со списком созданных и изменённых файлов, а `/task-gate` (проверка 2.7b) сверяет, что каждый из них попал в коммит. Файл, о котором отрапортовали, но которого нет на диске, — блокер: класс «рапорт о записи без записи» уже случался.

`docs/` под gitignore — правило неприменимо, gate отмечает это строкой в отчёте, но не блокирует.

## `todos/` — только внешняя блокировка

Признак: resume-триггер, по которому машинально видно «наступил / не наступил» — версия в реестре, дата, статус в консоли стора, число событий в аналитике. Ждём релиз upstream, ответ стора, репро от пользователя, накопление данных, устройство, действие владельца backend.

- Лимит `## Open` — **20 записей**. Уперлись — в списке завёлся бэклог, разобрать, а не дописывать 21-ю строку.
- **Перед созданием — grep по теме в `todos/`.** Есть запись про тот же компонент — дописать подраздел, не заводить вторую.
- `blocking_reason: user-deferred` — **запрещён**. Пользователь отложил → это `backlog/`.
- Раз в месяц — сверка триггеров фактом (Maven/npm, консоль стора, аналитика), не памятью. Просроченный триггер закрывают или переставляют дату явно.

Закрыто → `status: resolved` + `resolved:` во frontmatter → `git mv` в `todos/done/`, строка из `## Open` в `## Resolved`. Отменено → `status: cancelled`, туда же. Файл не удаляем: причина отказа ценнее самой задачи.

**Триггер создания — ровно два случая:** (а) пользователь явно просит зафиксировать; (б) задачу начали, и пользователь по ходу её откладывает (сказал «отложим», специалист вернул `NEEDS_DELEGATION` с отложенной делегацией, просится `// TODO:`, реализована одна платформа из двух).

**НЕ создавать** для «ждём проверки на проде», «снять диагностику после подтверждения», «вернуться, если всплывёт». Будет баг — задача вернётся вместе с багом; не будет — запись осядет мусором.

В коде вместо `// TODO:` — `// Pending: docs/todos/<файл>.md`, один anchor на запись.

## `backlog/` — «когда-нибудь»

Полировка, техдолг, идея, вторая платформа «по желанию», отложенный рефактор. Запись из `todos/` всплывает сама по триггеру; запись из `backlog/` берут руками, когда решили взять. Их нельзя обслуживать одним списком.

## Переезд файла ломает относительные ссылки

Чинить тем же коммитом: файл ушёл на уровень глубже → `../decisions/` становится `../../decisions/`, входящие ссылки → `done/<файл>.md`. Markdown об этом молчит, битая ссылка выглядит живой.

Проверять сразу: в проекте с тестами — тестом, резолвящим все относительные ссылки в `.md` (ссылки + совпадение `status` файла с папкой + строка в INDEX на каждый файл); без тестов — `grep` по старому имени перед коммитом. Тест сверяет ссылку со списком путей репозитория, **не** через `Path.exists()`: на Windows `exists()` принимает `a\b` за валидный путь и игнорирует регистр — тест зеленел бы локально и падал в Linux-CI.

## Дока разошлась с кодом → правим сразу

Правило действует для **всех** документов, прочитанных по ходу задачи (`docs/**`, проектный `CLAUDE.md`, README, дайджест `@knowledge-scout`), не только для документа текущей задачи. Устаревший путь, удалённый API, изменённое поведение, невалидный пример — правим в момент обнаружения.

Правка точечная, только разошедшийся фрагмент; источник истины — код; выводы документа не меняем. Расхождение шире одного фрагмента (документ описывает несуществующую архитектуру) — в шапку `**Статус:** устарело — <причина>`, переписывание в `todos/`. Актуализированные файлы перечислить в финальном ответе.
