# Документация субагентов уезжает вместе с MR сессии

## Что хотим

Документы, написанные субагентами по ходу задачи (`docs/active/`, `docs/solutions/`, `docs/decisions/`, `docs/archive/`), должны попадать в тот же merge request, что и код сессии. Сейчас доки могут остаться неотправленными: их пишет субагент, а стейджит и коммитит главный — если он этого не сделал, документация расходится с веткой и умирает в рабочем дереве.

## Почему это не однострочная правка

Требование напрямую конфликтует с действующим инвариантом. Во всех определениях субагентов и в скилле `specialist-workflow` записан hard scope: `git add` / `commit` / `push` — **запрещены**, коммиты делает только главный через `/commit`. У `doc-writer` этот запрет отдельно усилен прецедентом (коммит `fa141604` 2026-04-27, scope creep на 83 turns).

То есть выбор не «разрешить субагентам git», а какой из двух вариантов закрепить.

## Развилка, которую надо решить до реализации

**Вариант A — субагент стейджит, но не коммитит.** `doc-writer` получает право на `git add` строго внутри `docs/`, коммит остаётся за главным. Плюс: документ гарантированно попадает в индекс, даже если главный забыл. Минус: частичный пробой hard scope, надо переписывать запрет во всех агентах и держать его точным (`git add docs/` — да, всё остальное — нет).

**Вариант B — гейт на стороне главного.** Субагенты git не касаются вообще; `/task-gate` и `/commit` проверяют, что все файлы, созданные `@doc-writer` за задачу, попали в коммит, и блокируют закрытие при расхождении. Плюс: инвариант остаётся целым, проверка детерминирована. Минус: нужно передавать список созданных доков из `@doc-writer` главному — сейчас он возвращает только `ARCHIVED:` и `INDEX_ROW:`.

Предпочтение при прочих равных — B: правило, которое проверяется гейтом, надёжнее правила, которое каждый агент должен помнить.

## Что проверить при проработке

- **`docs/` бывает gitignored.** В части проектов документация не отслеживается git'ом (есть прецедент в памяти `@knowledge-scout` про устаревание gitignored-доков в worktree). Тогда «уехать вместе с MR» физически невозможно, и правило должно это детектировать, а не падать.
- **Worktree.** Задача идёт в отдельном worktree; доки пишутся туда же. Проверить, что ничего не пишется в основной checkout.
- **Фоновый режим.** `@doc-writer` работает с `run_in_background: true` и может закончить **после** того, как главный сделал коммит. Гейт обязан это учитывать, иначе проверка будет ложно-зелёной.
- Где закрепить итоговое правило — по скиллу `instruction-routing`: скорее всего `/task-gate` (проверка) плюс строка в `~/.claude/rules/docs-structure.md`.

## Решение (2026-08-03)

Выбран **вариант B**. Реализовано в той же сессии:

- `@doc-writer` во всех фазах возвращает строку `DOCS_WRITTEN:` со списком созданных и изменённых файлов (`none`, если не писал).
- `/task-gate` — новая проверка **2.7b**: сверяет каждый путь через `git status --porcelain`, добавляет недостающее к коммиту на Step 5. Файл, о котором отрапортовали, но которого нет на диске, — блокер. `docs/` под gitignore — warning, не блокер.
- Фоновый COMPLETE: результат дожидаются **до** Step 5; если коммит уже сделан, а файлы пришли позже — `--amend` для непушнутого коммита либо отдельный `docs: <slug>` для запушенного.
- Правило зафиксировано в `~/.claude/rules/docs-structure.md` и в списке проверок DoD в `CLAUDE.md`.

Hard scope субагентов не тронут: git по-прежнему только у главного.
