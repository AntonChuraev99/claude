# Платформенные числа для маркетинга приложений — снимок

Читает `@marketing-expert`. **Условие обращения:** считаешь бюджет или окно обучения кампании, сравниваешь CVR/CTR между сторами, планируешь CPP или store-A/B, разбираешь расхождение MMP ↔ консоль.

**Ни одно число отсюда не подставляется в решение без перепроверки** `WebSearch`/`WebFetch` по первоисточнику; дата проверки идёт в блок «Источники» ответа. Снимок стареет — платформы меняют пороги молча.

## Метрики сторов — что с чем нельзя сравнивать

- **iOS CVR** = downloads ÷ unique impressions.
- **Play** после отчётной смены июня-июля 2026 — CTR по уникальным кликам Install/Open/Pre-register; там же установки перешли с device-based на account-based счёт. **YoY-сравнения через эту границу невалидны.**
- Величины разные: не сравнивать, не складывать, не усреднять.
- **Консоль стора ≥ MMP по установкам структурно** (консоль считает установки, MMP — первые открытия): расхождение до ~10% не расследуется.

## Custom Product Pages (CPP)

- Меняют только: скриншоты, превью, promotional text, присвоенные ключи, диплинки.
- **Никогда не меняют:** имя, subtitle, иконку, описание.
- Набор ключей уникален на одну CPP; присвоение ключей идёт live без ревью, новые скриншоты требуют ревью.
- **Лимит CPP на приложение подтверждать в доке** — менялся в конце 2025, по памяти не называть.

## Лимиты store-экспериментов

**Apple — Product Page Optimization:**
- максимум 3 treatment-варианта, ровно один тест за раз, до 90 дней;
- долю трафика выбираешь ты, но результат Apple отдаёт на **≥90% confidence — порог не настраивается**;
- тест иконки возможен, только если все её варианты уже лежат в опубликованном бинарнике; победившая иконка уезжает со следующей версией.

**Google Play — listing experiments:**
- сравнение идёт с текущим листингом; MDE и confidence настраиваешь ты;
- минимум 7 полных дней при практическом дефолте 14, авто-стоп по сроку;
- исход: Winner / Draw / More data needed;
- порог confidence ≥90%, а для иконки и любого дорогого к откату изменения — 95%.

Порог фиксируется **до** старта там, где он вообще настраивается.

## Бюджетные флоры и окна обучения

По памяти не называются — подтверждать в справке кабинета с датой.

- **Google App campaigns:** дневной бюджет ≥50× target CPI для install-кампаний; ≥10× target CPA для in-app-action при ≥10 уникальных пользователях в день на оптимизационном событии; target action-кампании выше all-users на ≥20%.
- **Meta AAC:** ~50 событий на ad set за 7 дней; кап 9 iOS install-кампаний на app ID; ≤5 ad set в каждой.
- **TikTok:** Cost Cap ≥30× target CPA; Maximum Delivery ≥10× исторического CPA; на iOS доступен только Maximum Delivery.

## Перезапуск обучения при правках

Правки автокампаний обнуляют learning на всех платформах: **креативы добавляют, а не удаляют.** Окно называешь по платформе, а не одно на всех.

- **Google:** бюджет и таргет не чаще раза в 1-2 недели, шаг ±15-20%.
- **TikTok:** +2-5 креативов за раз, оценка не раньше 3 дней.
- **Meta AAC:** рестарт обучения при смене бюджета, креатива или типа атрибуции.
