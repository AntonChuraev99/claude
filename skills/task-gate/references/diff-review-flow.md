# Diff review — база, приём результатов, триаж (Step 2.3b)

Этот файл — механика прогона 2.3b. В `SKILL.md` остались только условия запуска и
строка статуса: секция срабатывает лишь в режиме `full`, а `lite`-прогоны её
пропускают целиком, поэтому держать эти правила в теле скилла значило платить за
них на каждом прогоне гейта.

**Читать целиком ДО спавна ревьюеров.** Промпты осей, smell baseline, fail-fast и
контекст-пакет — в соседнем [`diff-review-axes.md`](diff-review-axes.md).

## База ревью — вся ветка, а не дифф задачи

На повторном `full` — приращение. Берётся первая доступная:

1. **`reviewedSha`** из state-файла, если он предок HEAD
   (`git merge-base --is-ancestor <reviewedSha> HEAD`) — граница уже отревьюенного.
   Второй и третий `full`-прогон одной ветки смотрят только новое, а не ветку заново
   (Target improvements 2026-08-19: «не больше одного спавна 2.3b на ветку»; повторный
   полный проход — это тот же спавн, оплаченный дважды).
2. **`origin/<транк>`** на merge-bound ветке (транк — из
   `~/.claude/config/protected-branches.local.json`): первый `full` ревьюит то, что
   реально уедет в MR, включая задачи этой ветки, закрытые прошлыми `lite`-прогонами.
3. **`BASE_SHA`** — ветка не merge-bound (согласованная работа в транке, репозиторий
   профиля `~/.claude`).

Диапазон — от `git merge-base <база> HEAD` до **рабочего дерева**, не до HEAD. Две
причины разом: влитый в ветку транк (Step 6.0) в ревью не попадает (чужие коммиты не
наши), и ревью видит ещё не закоммиченное — 2.0 идёт до Step 5, поэтому
`<база>...HEAD` на типичном прогоне отдал бы ревьюерам пустой дифф.

## `reviewedSha` двигается только на успехе

Ревью закрылось без `❌` → записать `reviewedSha = HEAD` рядом с `lastGateSha` (5.2).
Был `❌` → **не записывать**, следующий прогон обязан посмотреть тот же диапазон ещё
раз. `lite`-прогоны `reviewedSha` не трогают.

**И только если с момента ревью ничего не изменилось.** Ревьюилось рабочее дерево на
момент 2.0, а `reviewedSha = HEAD` пишется в 5.2 — между ними лежат 2.4–2.7b (доки
`@doc-writer`), фиксы `static` HIGH, правки по self-check и коммит 5.1. Всё это уехало
бы в коммит со штампом «отревьюено», ни разу не показанное ревьюеру, а следующий
`full` начал бы уже за этой границей. Поэтому — сверка отпечатка:

```bash
git diff "$MB" | sha1sum        # снять в 2.0, сразу после сборки пакета
git diff "$MB" | sha1sum        # повторить в 5.2, ДО записи reviewedSha
```

Отпечатки совпали → писать `reviewedSha = HEAD`. Разошлись (что-то дописано после
фан-аута) → **не писать**, в отчёт `⚠️ reviewedSha not advanced: diff changed after
review`. Проверка `git status --porcelain` этот случай не ловит: 5.1.1 как раз всё
коммитит, и дерево к 5.2 чистое.

## Сколько агентов

Дефолт — **один** с обеими осями; два — только если дифф >30 файлов **или** трогает
деньги, безопасность, деплой (полное правило и обоснование —
[`diff-review-axes.md`](diff-review-axes.md) → «Две оси, один агент по умолчанию»).
Дифф без исполняемого кода — один агент при любом размере, smell baseline не применять.

**Повторный `full` по той же ветке** (`reviewedSha` уже записывался) → в бриф
добавляется строка convergence: новые находки уровня суждения и стилистики не
репортить, только корректность и требования. Второй проход по тому же коду обязан
сходиться, а не набирать новый слой замечаний.

## Приём результатов

Агенты уже запущены в 2.0 (fail fast, контекст-пакет, модель по оси — там же). Здесь —
**приём**: дождаться агентов, напечатать отчёты **раздельно по осям**, не сливая и не
переранжируя между ними. Секция `## Optional` печатается свёрнутой — «optional: N
пунктов», в починку не идёт.

## Триаж перед починкой — обязателен, делает главный сам

Находка (с любой оси и от L2) идёт в фикс, только если её `failure_scenario` проверен
по коду: открыть названный `file:line`, пройти сценарий, убедиться, что результат
действительно неверный. Проверка стоит одного `Read`; агент-фиксер на непроверенной
находке стоит холодного контекста плюс правки, которая чинит несуществующее.

- Сценарий подтвердился → в фикс.
- Сценарий не воспроизводится по коду → находка **отбрасывается**, строкой в отчёт:
  `triaged out: <находка> — сценарий не подтверждён`. В `docs/todos/` не класть: там
  только заблокированное внешним событием, а не отвергнутые гипотезы.
- Проверить нельзя без прогона (рантайм: гонка, insets, анимация, видео) → не фикс, а
  пункт в `VERIFY` с конкретным сценарием прогона.

## Починка

**Чинит один агент пачкой, не агент на ось.** Все подтверждённые находки уходят одним
брифом одному профильному специалисту (домен — по файлам фикса, правило `CLAUDE.md` →
«Прод-код пишет специалист»); находки разных доменов — по агенту на домен, но не по
агенту на ось и не по агенту на находку. Паттерн `/code-review --fix`: одна починка на
один проход ревью.

## Ось не вернулась

Агент упал или отменён → `⚠️ diff review incomplete: <ось>`, `reviewedSha` не двигать
**и `2.3b` оставить в `deferredChecks`**. Правило Re-entrancy «пункт отработал на
`full` → убрать из массива» здесь не применяется: отработал прогон, а не проверка.
Иначе гард Step 6 пропустит в merge ветку, которую свежий ревьюер так и не увидел.
