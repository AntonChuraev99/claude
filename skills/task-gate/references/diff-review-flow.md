# Diff review — база, приём результатов, триаж (Step 2.3b)

Этот файл — механика прогона 2.3b. В `SKILL.md` остались только условия запуска и
строка статуса. Ревью идёт в **обоих** режимах гейта, в `lite` — одним агентом; это
единственное ревью диффа на задачу.

**Читать целиком ДО спавна ревьюеров.** Промпты осей, smell baseline, fail-fast и
контекст-пакет — в соседнем [`diff-review-axes.md`](diff-review-axes.md).

## Фан-аут (2.0)

Ревью — самая долгая часть гейта, а находки нужны только к отчёту. Поэтому агенты
стартуют первыми, а 2.1–2.8 идут, пока они работают; приём — в 2.3b и 2.9.

`gate-prep.py` уже сделал механику: пакет диффа по базе 2.3b (`review.package`, база —
в шапке пакета), L1 (`l1.json`), второй пакет для L2 от `BASE_SHA`, если базы разошлись
(`review.l2_package`), отпечаток диффа для `reviewedSha`. Чужой диапазон L2 не отдавать:
агент примет его за свой скоуп.

**Бриф ревьюера 2.3b — обязательные строки:**

- путь к пакету и база; «дифф уже собран — `git diff` заново не гонять; шире хунка —
  `Read` по пути»;
- Spec-источник (активный документ задачи или Prompt Contract) и блок «Порог находки»
  из `diff-review-axes.md`;
- «не больше 25 вызовов инструментов, отчёт обязателен, непрочитанное — строкой
  `не просмотрено:`» — дописать **до** отправки, отправленный бриф не поправить;
- «ничего не редактируй, не коммить, не запускай сборки и тесты; твой продукт — отчёт».
  Хуки запись ревьюера не запрещают, держит только бриф;
- `review.repeat: true` → строка convergence (ниже);
- дифф без кода (`review.has_code: false`) → Standards = сверка с документированными
  правилами (`CLAUDE.md`, конвенции репозитория) и целостность ссылок на скиллы, агентов
  и файлы, smell baseline не применять.

Модель ревьюера не понижать — бриф несёт Spec-ось.

**Бриф L2 (`@bug-pattern-reviewer`)** — base ref (`base.sha`) **и** путь к пакету: без
base ref агент по контракту уходит в рабочее дерево. Обязательна та же строка «ничего не
редактируй, не коммить, не запускай сборки и тесты; твой продукт — отчёт»: на tools во
frontmatter не полагаться — frontmatter объявляет `Read, Grep, Glob, Bash`, а рантайм
выдаёт ему ещё `Write, Edit`. Просьбы «оцени runtime-находки» не писать — runtime-хиты
он судит сам и только на добавленных строках. Спавнится и при сбое L1 (`l1.error`):
сбой не доказывает, что `static` чист.

**Все вызовы `Agent` одним сообщением.** У `Agent` нет `run_in_background`: вызов
возвращается сразу, результат приходит уведомлением.

**Сторож.** `ListAgents` показывает «running» и у зависшего, а `general-purpose`
транскрипт не пишет вовсе — работает только потолок по времени:
`WATCHDOG_ZERO_SEC=0 WATCHDOG_MAX_SEC=900 sh ~/.claude/scripts/agent-watchdog.sh <output_file…>`
через `Bash(run_in_background)`, `output_file` — из ответа `Agent`. `CAP` → `SendMessage`
«заверши сейчас тем, что есть», ещё сторож на 180 с, затем `TaskStop` и
`⚠️ diff review incomplete`. Для L2 (транскрипт пишет) — дефолты: `STALLED-ZERO` →
`TaskStop` + один респавн, `STALLED` → как `CAP`. `GONE` закрывает сторож по одному
файлу — на остальные перезапустить. Все вернулись раньше → `TaskStop` сторожа.

**Второй ревьюер — только `full`**, по порогу из «Сколько агентов»: тогда Standards
получает `effort="medium"`, Spec — модель и effort сессии.

## База ревью — вся ветка, а не дифф задачи

На повторном прогоне — приращение. Берётся первая доступная:

1. **`reviewedSha`** из state-файла, если он предок HEAD
   (`git merge-base --is-ancestor <reviewedSha> HEAD`) — граница уже отревьюенного.
   Второй и третий прогон одной ветки смотрят только новое, а не ветку заново
   (Target improvements 2026-08-19: «не больше одного спавна 2.3b на ветку»; повторный
   полный проход — это тот же спавн, оплаченный дважды).
2. **`origin/<транк>`** на merge-bound ветке (транк — из
   `~/.claude/config/protected-branches.local.json`): первый прогон ревьюит то, что
   реально уедет в MR.
3. **`BASE_SHA`** — ветка не merge-bound (согласованная работа в транке).

Диапазон — от `git merge-base <база> HEAD` до **рабочего дерева**, не до HEAD. Две
причины разом: влитый в ветку транк (Step 6.0) в ревью не попадает (чужие коммиты не
наши), и ревью видит ещё не закоммиченное — 2.0 идёт до Step 5, поэтому
`<база>...HEAD` на типичном прогоне отдал бы ревьюерам пустой дифф.

## `reviewedSha` двигается только на успехе

Ревью закрылось без `❌` → записать `reviewedSha = HEAD` рядом с `lastGateSha` (5.2),
в любом режиме. Был `❌` → **не записывать**, следующий прогон обязан посмотреть тот
же диапазон ещё раз.

**И только если с момента ревью ничего не изменилось.** Ревьюилось рабочее дерево на
момент 2.0, а `reviewedSha = HEAD` пишется в 5.2 — между ними лежат 2.4–2.7b (документ
задачи), фиксы `static` HIGH, правки по self-check и коммит 5.1. Всё это уехало
бы в коммит со штампом «отревьюено», ни разу не показанное ревьюеру, а следующий
`full` начал бы уже за этой границей. Поэтому — сверка отпечатка: `gate-prep.py`
снимает sha1 диффа `merge-base → рабочее дерево` при сборке пакета, `gate-log.py
--review-clean` снимает его заново в 5.2 и пишет `reviewedSha = HEAD`, только если
отпечатки совпали. Разошлись (что-то дописано после фан-аута) → `reviewedSha` не
двигается, в «Заметки» `ℹ️ reviewedSha not advanced: diff changed after review`.
Проверка `git status --porcelain` этот случай не ловит: 5.1.1 как раз всё коммитит, и
дерево к 5.2 чистое.

## Сколько агентов

Дефолт — **один** с обеими осями; в `lite` — всегда один. В `full` два — только если
дифф >30 файлов **или** трогает деньги, безопасность, деплой (полное правило и
обоснование — [`diff-review-axes.md`](diff-review-axes.md) → «Две оси, один агент по
умолчанию»). Дифф без исполняемого кода — один агент при любом размере, smell baseline
не применять.

**Повторный прогон по той же ветке** (`reviewedSha` уже записывался) → в бриф
добавляется строка convergence: новые находки уровня суждения и стилистики не
репортить, только корректность и требования. Второй проход по тому же коду обязан
сходиться, а не набирать новый слой замечаний.

## Приём результатов

Агенты уже запущены в 2.0 (fail fast, контекст-пакет, модель по оси — там же). Здесь —
**приём**: дождаться агентов, напечатать отчёты **раздельно по осям**, не сливая и не
переранжируя между ними. Секция `## Optional` печатается свёрнутой — «optional: N
пунктов», в починку не идёт. Standards-находки уровня суждения gate не блокируют: не
починенные — `⚠️` в отчёт, решение за пользователем.

## Триаж перед починкой — обязателен, делает главный сам

Находка (с любой оси и от L2) идёт в фикс, только если её `failure_scenario` проверен
по коду: открыть названный `file:line`, пройти сценарий, убедиться, что результат
действительно неверный. Проверка стоит одного `Read`; агент-фиксер на непроверенной
находке стоит холодного контекста плюс правки, которая чинит несуществующее.

- Сценарий подтвердился → в фикс.
- Сценарий не воспроизводится по коду → находка **отбрасывается**, строкой в отчёт:
  `triaged out: <находка> — сценарий не подтверждён`. В `docs/todos/` не класть: там
  только заблокированное внешним событием, а не отвергнутые гипотезы.
- Проверить нельзя без прогона (рантайм: гонка, insets, анимация, видео) → не фикс, а
  пункт в `VERIFY` с конкретным сценарием прогона.

## Починка

**Чинит один агент пачкой, не агент на ось.** Все подтверждённые находки уходят одним
брифом одному профильному специалисту (домен — по файлам фикса, правило `CLAUDE.md` →
«Прод-код пишет специалист»); находки разных доменов — по агенту на домен, но не по
агенту на ось и не по агенту на находку. Паттерн `/code-review --fix`: одна починка на
один проход ревью.

## Ось не вернулась

Агент упал или отменён → `⚠️ diff review incomplete: <ось>` в отчёт, `reviewedSha`
не двигать: следующий прогон ветки ревьюит тот же диапазон. Step 6 это не блокирует —
пользователь подтверждает результат по отчёту, где эта строка стоит; решение
мержить без ревью — его, а не гейта (ослабление 2026-09-15).
