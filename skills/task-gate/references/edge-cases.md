# Task Gate — Edge Cases

Этот файл — extract из секции `## Edge cases` в `task-gate/SKILL.md`. Описание нестандартных ситуаций, в которые попадает скилл, и того, как реагировать.

## 1. Не git-репозиторий

Шаги, требующие git: 2.1, 2.2 (частично), 5.1.

**Действие:** пропустить с пометкой `✅ N/A (no git)`. Остальное прогнать как обычно.

Типичный кейс — пользователь работает в каталоге с конспектами, исследовательскими файлами, без `git init`. Скилл всё ещё может проверить субагентов, документ задачи, рекомендации.

## 2. Сессия без задачи (просто болтовня / исследование)

Скилл всё равно стоит запустить — он сам определит, что:
- `✅ no changes` (git clean),
- `✅ no agents` (специалистов не было),
- `✅ no doc needed` (правил DoD не активировано),
- Step 4 = `✅ no recommendations`.

Завершение через ~30 секунд. Это нормальный исход, не пугаться.

**Why оставлять запуск:** task-gate — это часть ритуала «закрытия контекста», и его прогон даже на пустой сессии формирует привычку и тренирует main-agent на корректную классификацию.

## 3. Скилл вызвали при недописанной задаче

Признаки:
- Есть незакоммиченные правки.
- В коде явные `TODO:` / `FIXME:` без anchor (см. Step 2.8).
- Главный агент сам понимает, что задача не завершена (есть `// implement me`, undefined fields, незакрытые блоки).

**Действие:**
- Вердикт `❌ NOT READY`, перечислить что осталось.
- **Не** пытаться «дозавершить» — это работа главного агента, а не скилла.
- Возвращать управление главному агенту, чтобы тот закончил задачу.

## 4. Проверка фактов документа не проходит (2.4)

`docs-facts-guard` отдал `LINK`/`PATH` > 0 после того, как претензии уже закрывали, либо `IDENT` упирается во внешний код (SDK, чужой репозиторий, CLI-флаг).

**Действие:**
1. `LINK` — только правка: относительная ссылка на несуществующий файл бессмысленна, маркером не закрывается (хук её и не снимает). Не исправляется → `❌ NOT READY`.
2. `PATH` — правка; путь вне репозитория (gitignored-файл, чужой репо) — `(не проверено — <почему>)` в той же строке.
3. `IDENT` из внешнего источника — `(не проверено — Gemini API)` либо `источник: <дока>` в той же строке; `NUMBER` из инструмента — `источник:` в строке. Маркер без причины — не закрытие.
4. Претензий больше ~20 на документ — это не «шумный хук», а документ, написанный по памяти: перечитать по файлам, не закрывать пачкой маркеров. Легаси-претензии старого документа в gate не приходят (`--base`); нужен полный аудит — `--all`.

## 5. Несколько задач за сессию — gate не запускался после прошлых

Штатно несколько задач за сессию — **не edge case**: gate запускается на каждую задачу по её завершении, скоуп — дифф от `lastGateSha` (SKILL.md → «Re-entrancy»). Edge остаётся один: gate **забыли** прогнать после предыдущих задач, и к текущему запуску накопилось 2+ незакрытых задач в одном диффе.

**Действие по умолчанию:** прогон покрывает **последнюю** «логическую задачу» (последний Prompt Contract); в отчёте пометить `⚠️ N earlier tasks un-gated`.

Если пользователь хочет проверить всё накопленное — запросить уточнение через `AskUserQuestion`:

| Опция | Действие |
|---|---|
| **Проверить только последнюю задачу** | По умолчанию. Стандартный прогон gate. |
| **Проверить все задачи последовательно** | Прогнать gate N раз (по прогону на задачу, `lastGateSha` двигается после каждого), отчёт по каждой отдельно, общий verdict — худший из всех |
| **Только финальный коммит и общий статус** | Skip subagent sanity / документ задачи / recommendations, проверить только `git status` + наличие коммита |

## 6. Фоновый субагент всё ещё работает

Признаки: ревьюер 2.0 или другой фоновый агент задачи не вернул результат, а главный дошёл до Step 5.

**Действие:**
1. **Дождаться** уведомления о завершении — его результат входит в вердикт (2.3b / 2.9).
2. Завис надолго — таймаут 2 минуты, после — пометка `⚠️ <agent> hung`, спросить пользователя.

**Не блокировать диалог** долго: если ответ затягивается, дать пользователю промежуточный статус и спросить, ждать ли.

## 7. Строка статистики (2.6) не влезает в таблицу

Формат — 5 колонок (`| дата | project | task | Шагов | files |`) в таблице `## Session Log (с 2026-09-15)`. Старая таблица `## Session Log` на 10 колонок — история, в неё новые строки не писать. Текст `task` с `|` внутри ломает таблицу — заменить на `/`.

## 8. Рекомендация из Step 4 указывает на out-of-scope plugin

Если recommendation предлагает менять Anthropic-managed plugins/skills (`compound-engineering:*`, `vercel:*`, `cloudflare:*`, `figma:*`, `amplitude:*`):

**Действие:**
- НЕ записывать в queue (даже как LOW).
- В summary показать строку `⊘ X recs rejected (out-of-scope)`.
- Это страховка от мусора в queue.

Подробности — `~/.claude/recommendations/README.md` → секция «Best-practice критерии классификации».

## 9. Auto-commit упал на pre-commit hook

`/commit` вернул non-zero exit, в stderr — текст pre-commit hook'а (detekt, lint, type-check).

**Действие:**
- Пометить `❌ auto-commit failed: pre-commit hook`.
- **Не** заявлять задачу завершённой, не игнорировать `--no-verify`.
- В финальный отчёт включить:
  - Точный текст ошибки.
  - Файлы, на которые ругается hook.
  - Конкретные исправления (если очевидны).
- Передать управление пользователю, чтобы тот исправил и повторил.

**Запрещено:** ставить `--no-verify` или другие байпасы хука без явного запроса пользователя (см. глобальный `CLAUDE.md` → git-protocol).

## 10. State-файл re-entrancy потерян или повреждён

`task-gate-state.json` в session-scratchpad отсутствует (первый прогон в сессии — норма) или не парсится.

**Действие:**
- Не падать. BASE_SHA — fallback-цепочка из SKILL.md → «Re-entrancy»: START_SHA начала сессии, иначе рабочее дерево без `--base`.
- Once-проверки (`hookSetup`, `activeHygiene`) выполнить заново — они идемпотентны, повтор безопасен.
- Повреждённый файл **перезаписать** валидным состоянием при закрытии gate, не чинить вручную.
