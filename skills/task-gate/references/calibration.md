## Источник `iterations`

Поле берётся из `Шагов: N`, которое главный агент передаёт в промпте `@doc-writer COMPLETE`. Сам doc-writer его не пересчитывает.

**Правила подсчёта `N`.** Шаг — одна попытка двинуть GOAL, ограниченная валидацией (build/test pass) или обнаружением неверного подхода:

- `Edit` → PASS = 1
- `Edit` → FAIL → fix → PASS = 2
- делегация специалисту (любое число правок внутри) = 1
- неверный подход переписан = +1

**Не шаг:** `/commit`, `/task-gate`, скауты, фазы `@doc-writer`, `git status/diff/log`, чтение файлов, отчёты, операции с задачами.

**Суффикс `(approximate)`** означает, что counter упал на fallback `grep -c "### Итерация "` — это измеряет частоту делегирования, а не реальные шаги. Такие записи помечать, чтобы при чтении статистики было видно, что число неточное.

## Зачем это поле

`iterations` — единственная метрика в `STATS_ROW`, показывающая, сколько попыток реально стоила задача. Остальные колонки (`files_edited`, `solutions_read`, `memory_hits`, `errors_avoided`) описывают объём и переиспользование знаний, но не цену пути к результату. Занижение здесь делает всю строку бесполезной: аудит 2026-05-11 показал расхождение до −90% на коротких задачах, когда счёт шёл по числу делегаций.
