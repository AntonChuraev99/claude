# Подсчёт `Шагов: N` для строки статистики

Extract из Step 2.6 `task-gate/SKILL.md`: правила подсчёта поля `Шагов`, которое главный пишет в строку статистики задачи и в шапку документа задачи на COMPLETE (`doc-task`).

> **Калибровка по complexity отключена (2026-08-03).** Классификация задач на Trivial/Standard/Complex упразднена, вместе с ней — формула compound effect с хардкод-baseline на класс, триггер перекалибровки по p75 и правила сброса стека. Таблица `## Compound Effect` в `~/.claude/stats/doc-writer.md` остаётся как исторические данные: новые строки в неё не считаются, старые не переписываются. Актуально только то, что ниже.

## Источник `iterations`

Поле считает главный агент по transcript задачи — до 2026-09-15 оно передавалось субагенту `doc-writer` в COMPLETE-промпте; теперь идёт прямо в строку 2.6.

**Правила подсчёта `N`.** Шаг — одна попытка двинуть GOAL, ограниченная валидацией (build/test pass) или обнаружением неверного подхода:

- `Edit` → PASS = 1
- `Edit` → FAIL → fix → PASS = 2
- делегация специалисту (любое число правок внутри) = 1
- неверный подход переписан = +1

**Не шаг:** `/commit`, `/task-gate`, скауты, документ задачи (`doc-task`), `git status/diff/log`, чтение файлов, отчёты, операции с задачами.

**Суффикс `(approximate)`** — число восстановлено не по transcript, а по `## Лог итераций` документа (например, gate прогоняется в новой сессии после обрыва): лог измеряет частоту делегирования, а не реальные шаги. Такие записи помечать, чтобы при чтении статистики было видно, что число неточное.

## Зачем это поле

`Шагов` — единственная метрика строки, показывающая, сколько попыток реально стоила задача; `files` описывает объём, но не цену пути к результату (колонки `solutions_read` / `memory_hits` / `errors_avoided` упразднены 2026-09-15 — считались grep'ом по словам документа и ничего не измеряли). Занижение здесь делает всю строку бесполезной: аудит 2026-05-11 показал расхождение до −90% на коротких задачах, когда счёт шёл по числу делегаций.
