# Скриншот-цикл в гейте — проверка инфраструктуры (Step 2.2b)

Механика секции 2.2b. В `SKILL.md` остались триггер и строки статуса: секция
срабатывает, только когда дифф трогает вёрстку, а на всех прочих задачах эти правила
грузились бы впустую.

Инвариант `CLAUDE.md` → «Вёрстка — проверяется картинкой, а не пользователем»,
процедура съёмки — скилл `screenshot-driven-ui`.

## Таблица по поверхностям

Отчёт даёт **строку на каждый экран или компонент**, который задача изменила **либо
впервые сделала достижимым**, а не общий вердикт по задаче. В строке — путь к кадру,
который агент открывал, и что на нём видно, либо `не снят` + причина. **Кадры соседней
поверхности чужую строку не закрывают.**

## Инфраструктура проверяется по МОДУЛЮ изменённого файла, а не по репозиторию

Roborazzi подключается в `build.gradle.kts` модуля и держит голдены в
`<module>/src/androidHostTest/roborazzi/`; «в проекте кадры есть» не говорит ничего про
этот модуль.

Снипет ниже покрывает **только Compose-модули**; для web-диффа (`.tsx`, стили)
инфраструктура проверяется наличием Playwright-конфига и каталога снапшотов рядом с
изменённым компонентом — пустой список `NONE` на web-диффе означает «проверка не
проводилась», а не «инфраструктура есть».

```bash
git diff --name-only <BASE_SHA> -- '*.kt' | grep -Ei 'screen|content|dock|bar|sheet|card|row|panel|designsystem' |
while read f; do d=$(dirname "$f"); while [ "$d" != "." ]; do [ -f "$d/build.gradle.kts" ] && { echo "$d"; break; }; d=$(dirname "$d"); done; done | sort -u |
while read m; do [ -d "$m/src/androidHostTest/roborazzi" ] && echo "OK   $m" || echo "NONE $m"; done
```

## Вердикт

- Все строки таблицы несут открытый кадр → `✅`.
- Модуль в списке `NONE` → `⚠️ no screenshot infra: <модуль>` + развилка «завести
  сейчас / отложить» вынесена пользователю через `AskUserQuestion`, отложенное —
  строкой в `docs/todos/`.
- Строка без кадра и без причины → `❌` : вёрстка не проверена, а не «проверена ручным
  сценарием».

## Впервые достижимая поверхность идёт в таблицу, даже если её код не менялся

Новый route, новая кнопка, новый ряд входов или deep link на существующий экран — это
отгрузка экрана в новой роли: он мог годами жить редко открываемым и не выдерживать
роль главной двери. Ищется в диффе навигации: новый `AppNavRoute` либо новый call-site
`navigateTo*` на существующий экран.

> Прецедент 2026-08-17 (`feat/ux-overhaul`): ветка пристроила к экрану Analyze четыре
> новые двери, сам экран при этом почти не менялся. Гейт спросил «есть ли
> инфраструктура в проекте» — Roborazzi стоял в 4 модулях из 13, ответ «есть», люк
> `⚠️ no screenshot infra` не открылся ни разу. За ветку сняли десятки кадров дверей и
> **ноль** кадров того, куда двери ведут; шесть карточек типа источника занимали
> ~336dp — весь первый экран — и это увидел владелец, а не гейт.
