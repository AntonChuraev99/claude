# Diff review двумя осями — Standards + Spec

Механика пункта 2.3b. Источник метода — скилл `code-review` (mattpocock), адаптирован под наш процесс: базовая точка берётся из правил 2.3b (`reviewedSha` → `origin/<транк>` → `BASE_SHA`), роль «issue tracker» играет активный документ задачи или Prompt Contract.

## Две оси, один агент по умолчанию

Изменение может пройти одну ось и провалить другую:

- Код следует всем конвенциям, но реализует не то, о чём просили → **Standards pass, Spec fail.**
- Код делает ровно то, что просили, но ломает конвенции проекта → **Spec pass, Standards fail.**

Поэтому осей всегда две и отчёт по ним **всегда раздельный** — находки не мержатся и не переранжируются между осями. Раздельность обеспечивает формат ответа, а не число агентов.

**Дефолт — один агент с обеими осями в брифе.** Дефолт Anthropic для ревью диффа — один субагент на весь дифф (`/code-review`), а не осевой фан-аут; их дока по costs прямо предупреждает, что команда агентов стоит порядка 7× токенов. Наш прежний дефолт (два агента + L2 = три холодных контекста на один дифф) от этого расходился и оплачивал сбор одного и того же контекста трижды.

**Два агента — только когда цена ошибки перевешивает,** любое из условий:

- дифф больше **30 файлов** — на таком объёме один контекст начинает ранжировать: находки сильной оси маскируют слабую;
- дифф трогает **деньги, безопасность или деплой** — платежи и подписки, аутентификация и права доступа, правила безопасности БД, секреты, CI/CD и инфраструктура выкатки.

Ни одно не выполнено → один агент, раздельные секции `## Standards` и `## Spec` в ответе. Риск взаимного маскирования на диффе такого размера принимается сознательно: он дешевле второго холодного контекста.

**Дифф без исполняемого кода** (правила харнесса, `docs/**`, `.md`, `review-rules/*.yaml`, локализация, ассеты) — всегда один агент, и **smell baseline Фаулера не применять**: он про код.

## Fail fast — до спавна агентов

База ревью (`<база>`) — `reviewedSha` из state-файла, если он предок HEAD; иначе `origin/<транк>` на merge-bound ветке; иначе `BASE_SHA` (полное правило и условия записи `reviewedSha` — 2.3b в SKILL.md).

1. Режим гейта — `full`. `lite` → агентов не спавнить, `⏸ deferred to pre-merge (full) gate`.
2. `git rev-parse <база>` — ref резолвится.
3. `git diff --stat $(git merge-base <база> HEAD)` — дифф непустой (от точки ветвления до **рабочего дерева**: ревью идёт до коммита, см. «Контекст-пакет»).
4. Определить число агентов по правилу секции выше: дефолт — **один** агент с обеими осями; два параллельных — только если дифф >30 файлов **или** трогает деньги, безопасность, деплой. Кода в диффе нет (документация, `.md`, правила харнесса, `review-rules/*.yaml`, локализация, ассеты) → один агент и без smell baseline при любом размере.
5. Собрать контекст-пакет (секция ниже) — до спавна, один раз на все оси.

Любая из проверок провалилась → `⚠️ diff review skipped (<причина>)`, агентов не спавнить. Дешевле упасть здесь, чем внутри двух субагентов.

## Контекст-пакет — дифф собирается один раз

Standards, Spec и `@bug-pattern-reviewer` смотрят на **один и тот же дифф**. Пустить каждого собирать его самостоятельно — три холодных `git diff` плюс три независимых обхода изменённых файлов; на ветке в десятки файлов это и есть основная часть времени ревью. Инвариант тот же, что для reader-стадии workflow (`CLAUDE.md` → «В workflow общий контекст собирает первая стадия»): **discovery оплачивается один раз**.

Главный собирает пакет **до** спавна и передаёт агентам **путь**, не содержимое — бриф пере-prefill'ится на каждом вызове агента, поэтому дифф в `prompt` не кладётся ни при каком размере (`CLAUDE.md` → «Всё, что длиннее ~8k символов, — во внешний файл»):

```bash
git add -N .                              # новые файлы — в дифф (см. ниже)
MB=$(git merge-base <база> HEAD)          # точка ветвления
PKG="<session-scratchpad>/review-package-$(git rev-parse --short HEAD).md"
{ echo "# Review package"; echo;
  echo "БАЗА: $MB (merge-base <база> HEAD) → рабочее дерево"; echo;
  echo "## Файлы";   git diff --stat "$MB"; echo;
  echo "## Коммиты"; git log --oneline "$MB"..HEAD; echo;
  echo "## Дифф";    git diff "$MB"; } > "$PKG"
```

**Почему `git add -N .` первой строкой.** `git diff` не показывает неотслеживаемые файлы вовсе — новый модуль, новый компонент, новый док задачи не попали бы ни к одной оси, а отчёт выглядел бы пройденным ревью. `git add -N` (intent-to-add) регистрирует их в индексе как пустые, и дифф показывает всё содержимое как добавленное; проверено: до `add -N` файл в `git diff --stat` отсутствует, после — виден. Коммит это не делает и содержимого не стейджит, `.gitignore` не обходит (игнорируемое остаётся невидимым — так и надо). Дифф собран → индекс можно вернуть `git reset -q -- <пути>`, если гейт ещё не дошёл до Step 5.

**Почему `merge-base`, а не `<база>...HEAD`.** Ревью идёт в 2.0, коммит — в Step 5: на момент фан-аута правки задачи, как правило, ещё **не закоммичены**, а `<база>...HEAD` сравнивает коммиты и незакоммиченного не видит вовсе. Пакет вышел бы пустым, а оси честно отчитались бы «находок нет» — худший из возможных исходов, потому что выглядит как пройденное ревью. `git diff $MB` берёт всё от точки ветвления до рабочего дерева: и коммиты задачи, и ещё не закоммиченное. Голый `git diff <база>` для этого не годится — если транк ушёл вперёд, он покажет чужие коммиты вывернутыми наизнанку, как удаления.

Дифф крупнее ~2 МБ → пересобрать без шума: `git diff "$MB" -- ':(exclude)*.lock' ':(exclude)*-lock.json' ':(exclude)*.svg'`, а в бриф добавить строку, **что** усечено и по какому правилу. Молча урезанный пакет читается агентом как полный дифф — это ложное «находок нет».

В бриф каждой оси: путь `PKG`, база и строка «дифф уже собран — `git diff` заново не гонять; нужен более широкий контекст файла, чем хунк, — `Read` по конкретному пути». Запрет точечный: открывать файлы агент вправе, пересобирать дифф — нет.

**Ревью-агенты read-only.** Они спавнятся фоном (2.0), а фоновый агент не наследует PreToolUse-хуки — запрет на запись держится только брифом. Строка «ничего не редактируй, не коммить, не запускай сборки и тесты; твой продукт — отчёт» обязательна в бриф каждой оси. `@bug-pattern-reviewer` ограничен ещё и своим frontmatter, general-purpose — ничем, кроме этой строки.

## Источник Spec

По порядку, первый найденный:

1. Активный документ задачи в `docs/active/` (GOAL + критерии).
2. Prompt Contract этой задачи (GOAL / CONSTRAINTS / OUTPUT / FAILURE) из диалога.
3. Ссылка на issue или задачу Jira, если она была в брифе.
4. Ничего не найдено → Spec-ось пропускается, в отчёте `Spec: ⚠️ no spec available`.

## Источники Standards

Проектный `CLAUDE.md`, `.claude/rules/*`, `CONTRIBUTING.md`, конфиги линтеров — **и smell baseline ниже**.

Два правила связывают baseline:

- **Проект перекрывает baseline.** Документированное правило проекта всегда выигрывает; там, где оно одобряет то, что baseline пометил бы, smell подавляется.
- **Baseline — всегда суждение**, а не жёсткое нарушение: формулировка «возможно, Feature Envy». Нарушение документированного правила может быть жёстким, smell — нет.
- **Пропускать то, что уже ловит тулинг** (detekt, ktlint, eslint, tsc): дублировать линтер ревьюером — шум.

## Smell baseline (Fowler, *Refactoring*, ch. 3)

Применяется даже когда проект не документирует ничего. Читается как *что это* → *как чинить*:

- **Mysterious Name** — функция, переменная или тип, чьё имя не говорит, что он делает или хранит. → переименовать; честное имя не находится — мутный дизайн.
- **Duplicated Code** — одна и та же форма логики появляется в нескольких хунках или файлах диффа. → извлечь общее, звать из обоих мест.
- **Feature Envy** — метод лезет в данные чужого объекта чаще, чем в свои. → перенести метод к данным, которым он завидует.
- **Data Clumps** — одни и те же несколько полей или параметров всё время ездят вместе (тип, который просится родиться). → собрать в один тип, передавать его.
- **Primitive Obsession** — примитив или строка вместо доменного понятия, заслуживающего своего типа. → дать понятию свой маленький тип.
- **Repeated Switches** — один и тот же `when`/`switch` по одному и тому же типу повторяется по диффу. → полиморфизм либо одна общая карта.
- **Shotgun Surgery** — одно логическое изменение заставляет править россыпь файлов. → собрать то, что меняется вместе, в один модуль.
- **Divergent Change** — один файл или модуль правится по нескольким несвязанным причинам. → разделить так, чтобы модуль менялся по одной причине.
- **Speculative Generality** — абстракции, параметры или хуки под потребности, которых в спеке нет. → удалить, заинлайнить обратно до появления реальной нужды.
- **Message Chains** — длинная навигация `a.b().c().d()`, от которой вызывающий не должен зависеть. → спрятать обход за одним методом первого объекта.
- **Middle Man** — класс или функция, которые почти только делегируют дальше. → убрать, звать цель напрямую.
- **Refused Bequest** — наследник игнорирует или переопределяет большую часть унаследованного. → отказаться от наследования в пользу композиции.

## Промпты субагентов

Спавн — в 2.0 (`SKILL.md`), **одним сообщением вместе с L2**, после чего гейт идёт в 2.1, не дожидаясь ответов (у `Agent` нет `run_in_background` — вызов и так возвращается сразу).

- **Дефолт — один вызов** `Agent(subagent_type="general-purpose")`: оба промпта ниже в одном брифе, ответ раздельными секциями `## Standards` и `## Spec`. Модель **не** понижать — бриф несёт Spec-ось.
- **Два вызова** — только по порогу секции «Две оси, один агент по умолчанию» (>30 файлов либо деньги/безопасность/деплой): отдельный Standards (`model: "sonnet"`) и отдельный Spec (модель сессионная).
- **Дифф без кода** — один вызов; блок smell baseline в бриф не класть, вместо него «Standards здесь = сверка с документированными правилами репозитория и целостность ссылок на скиллы, агентов и файлы».

Обе оси получают **путь к контекст-пакету**, а не команду диффа, и строку read-only-запрета (секция выше).

**Standards** — `model: "sonnet"`. Сверка диффа с задокументированными правилами и с фиксированным списком смелов — аудит по готовому чеклисту: источники названы, baseline лежит в брифе целиком, простора для вывода мало. Политика моделей — improvements 2026-06-01: `sonnet` там, где `opus` не даёт прироста на research/audit. В бриф: путь к пакету, база, пути найденных standards-источников и **весь smell baseline текстом** — другого доступа к нему у субагента нет. Задача: «Отчёт — по файлам и хункам: (а) каждое место, где дифф нарушает документированное правило: процитируй правило (файл + пункт); (б) каждый замеченный smell из baseline: назови его и процитируй хунк. Разделяй жёсткие нарушения и суждения — нарушение документированного правила может быть жёстким, smell всегда суждение, документированное правило проекта перекрывает baseline. Пропускай всё, что ловит тулинг. До 400 слов.» Плюс блок «Порог находки» ниже — дословно.

**Spec** — модель **не** переопределять, наследуется сессионная. Это единственная ось, ловящая «сделано не то, о чём просили»; на ней не экономят. В бриф: путь к пакету, база, текст или путь спеки. Задача: «Отчёт: (а) требования спеки, которые отсутствуют или сделаны частично; (б) поведение в диффе, о котором не просили (scope creep); (в) требования, которые выглядят реализованными, но реализация похожа на неверную. К каждой находке цитата строки спеки. До 400 слов.» Плюс блок «Порог находки» ниже — дословно. Пункт (в) требует того же `failure_scenario`: «реализация похожа на неверную» без сценария, при котором она даёт неверный результат, — не находка.

## Порог находки — в бриф каждой оси дословно

Инвариант `CLAUDE.md` → «Review-задачу формулировать порогом доказуемости». Блок ниже кладётся в бриф **каждой** оси как есть; фильтр по severity («only high», «не придирайся») не ставить ни в каком виде — модель исполняет его буквально и молчит о найденном.

> Репортить то, что затрагивает **корректность или заявленные требования**. Каждая находка обязана нести: якорь `file:line` из диффа, и `failure_scenario` — конкретные вход или состояние → неверный результат или падение. Утверждение о поведении требует цитаты кода, а не вывода из имени функции или переменной.
>
> **Не находка** (в отчёт не идёт): «выглядит подозрительно», «может сломаться, если», гонка без пути исполнения, отсутствие обработки ошибок там, где вызов не падает, перф без замера, то, что ловит линтер или компилятор, стилистика, эквивалентная по поведению переписка.
>
> Что не дотянуло до порога, но кажется важным — **одной строкой** в секции `## Optional` в конце, без разбора и без сценария. Эта секция ненормативна: главный её не чинит.

Если тул `ReportFindings` доступен агенту — репортить им, его схема (`failure_scenario`, `verdict`, `severity`, `file`, `line`) и есть этот порог в машинном виде.

## Агрегация

Два отчёта под заголовками `## Standards` и `## Spec`, дословно или слегка причёсанные — независимо от того, пришли они от одного агента или от двух. **Не мержить и не переранжировать** — раздельность и есть смысл метода. В конце строка: сколько находок на каждой оси и худшая находка **внутри каждой** оси. Победителя между осями не выбирать.

Секция `## Optional` (что не дотянуло до порога) печатается **свёрнутой в одну строку** — «optional: N пунктов» — и в починку не идёт. Разворачивать её только по прямой просьбе пользователя.

**Повторный `full` по той же ветке — convergence.** Ревью уже проходило по этой ветке (`reviewedSha` был записан хотя бы раз) → в бриф добавляется строка: «это повторное ревью ветки; новые находки уровня суждения и стилистики не репортить, только то, что затрагивает корректность или требования». Паттерн Anthropic (REVIEW.md, re-review convergence): второй проход по тому же коду обязан сходиться, а не набирать новый слой замечаний. Порог доказуемости при этом не меняется — снимается только повторный слой ниток.
