# Артефакт для подтверждения (5.1b)

Пользователь подтверждает результат по отчёту gate — значит, в отчёте лежит то, что он может открыть и потрогать, а не только таблица статусов. До 2026-09-14 отчёт заканчивался строкой «подтверди», и проверка сводилась к чтению диффа глазами либо к ручной сборке на стороне пользователя.

## Класс артефакта — по платформе диффа

Приоритет сверху вниз; fallback — только с названной причиной, доказанной выводом команды, а не предположением.

| Платформа диффа | Первый приоритет | Fallback |
|---|---|---|
| Web — React/Next.js, wasmJs, любой браузерный | живой `http://localhost:<port>/<путь до экрана>`, dev-server запущен и отвечает | PNG из Playwright / кадры 2.2b + причина, почему сервер не поднят |
| Android | debug APK, собранный под физическое устройство пользователя: путь + состояние устройства; **установка — только с согласия** | APK без устройства (не подключено) + кадры эмулятора |
| Остальное — CLI, backend, скрипт, конфиг, доки, харнесс `~/.claude` | то, что показывает результат: вывод команды или теста, `curl` на endpoint, лог, PNG, путь к файлу + ключевой фрагмент, страница `Artifact` для отчётов | — |

Один дифф на несколько платформ (KMP: `androidMain` + `wasmJs`) → артефакт на каждую.

## Web — localhost

1. Поднять dev-server **из worktree задачи** скиллом `run` (ищет проектный скилл запуска; иначе `npm run dev`, `./gradlew :<module>:wasmJsBrowserDevelopmentRun` и т.п.), `run_in_background: true`.
2. Проверить, что отвечает: `curl -sI http://localhost:<port>` → 200, либо Playwright `browser_navigate` + `browser_take_screenshot` — PNG в scratchpad, путь в отчёт **дополнением** к URL, не вместо него.
3. URL — с портом и путём до изменённого экрана (`http://localhost:3000/settings`), не корень.
4. Сервер **живёт до подтверждения**: в Step 5 не гасить. Id фоновой задачи и URL записать в `artifactServer` state-файла `task-gate-state.json`. Гасит Step 6 п. 5 — до `ExitWorktree`, иначе процесс держит каталог и уборка падает.
5. **Повторный прогон gate** (пользователь назвал дефект → фикс → gate #2): сервер из `artifactServer` остановить (`TaskStop <taskId>`) и поднять заново — `200` от старого процесса доказывает живость, не свежесть, а dev-server без HMR отдаёт сборку до фикса. Порт занят **своим** процессом — это не fallback, а пропущенный `TaskStop`.
6. Не поднялся (нужен секрет, порт занят чужим процессом, сборка падает) → fallback + причина с выводом команды.

## Android — APK под физическое устройство, установка только с ведома

1. Модуль-приложение — по плагину `com.android.application` (алгоритм с фильтром `apply false` и AGP 9 split — `commands/install-device.md` Шаг 2). Сборка `./gradlew :<module>:assembleDebug`, APK — `<module>/build/outputs/apk/debug/*.apk`. `installDebug` не использовать — ставит на все устройства разом.
2. Устройство: `adb devices -l`; физическое = `state == device` и serial не `emulator-*`. В отчёт `MODEL (SERIAL)` либо `устройство не подключено`.
3. **Согласие на установку — одно из двух, и оно относится к сборке после последней правки кода:** (а) пользователь попросил поставить результат **после** последней правки («как починишь — поставь на телефон», «залей на устройство» уже по готовому фиксу); (б) после отчёта — `AskUserQuestion`: «Установить на <MODEL> сейчас (Recommended)» / «Сам поставлю» / «Не нужно». Не согласие: `/install-device` или просьба поставить, высказанные **до** правки (репро бага на старой сборке) — новая сборка ставится только по (б); согласие из прошлой задачи или сессии. Цена ошибки — `/install-device` при конфликте версии или подписи делает `uninstall` сам, данные приложения теряются. **Без ответа — не ставить:** `adb install`, `installDebug`, `/install-device` не вызывать. Согласие есть → `/install-device` (ответ на вопрос для него — явный запуск; собирает, ставит, запускает).
4. Отчёт: `APK: <путь> (<размер>, <mtime>)` · `Устройство: <MODEL (SERIAL)> | не подключено` · `Установка: по согласию <когда> | ждёт ответа | не запрошена`.
5. Устройства нет → APK + причина; кадры эмулятора как дополнение (`/install-emulator` согласия не требует — эмулятор не устройство пользователя).

## Остальное

- Backend / API: `curl` или тестовый запрос к локально поднятому сервису — код ответа и тело.
- CLI / скрипт: команда и её вывод на реальном входе.
- Конфиг, правило, дока, харнесс `~/.claude`: путь + ключевой фрагмент 5–15 строк; резидентное правило (`CLAUDE.md`, `rules/*` без `paths`) — ещё и факт, что оно загрузится (размер в бюджете `claude-md-size-guard`).
- Отчёт, аналитика, план: страница `Artifact` либо путь к файлу.
- Вёрстка: кадры уже в таблице 2.2b — в 5.1b ссылка на неё, не дубль.

## Что артефактом не считается

Таблица статусов gate · дифф · «тесты зелёные» без вывода · пересказ «работает» без пути, URL или вывода · кадр соседней поверхности · сборка, которую пользователь должен сделать сам.

## Статусы 5.1b

`✅ localhost <url>` · `✅ APK <путь>; установка: <…>` · `✅ <вид>: <путь | вывод>` · `⚠️ fallback: <вид> — <причина>` · `❌ no artifact` → вердикт `NOT READY`, главный возвращается в работу.
