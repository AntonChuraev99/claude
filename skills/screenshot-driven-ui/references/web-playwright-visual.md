# Web: визуальная проверка вёрстки

Цикл тот же: собрать компонент на фейковых данных → снять на матрице viewport'ов → **посмотреть PNG самому** → итерация → и только потом живой прогон в браузере.

## React / Next.js — Playwright

Матрица задаётся проектами конфига, не размножением тестов:

```ts
// playwright.config.ts
export default defineConfig({
  projects: [
    { name: 'mobile',  use: { viewport: { width: 390,  height: 844  } } },
    { name: 'tablet',  use: { viewport: { width: 768,  height: 1024 } } },
    { name: 'desktop', use: { viewport: { width: 1440, height: 900  } } },
  ],
})
```

## Откуда берутся фейковые состояния

Порядок предпочтения, от дешёвого к дорогому:

1. **Storybook**, если он в проекте есть: story = состояние, снимать с них.
2. **Component testing** (`@playwright/experimental-ct-react`) — компонент монтируется с нужными props прямо в тесте, приложение поднимать не надо.
3. **Мок сети** — `page.route()` подменяет ответ API на фикстуру; страница остаётся нетронутой.
4. Dev-only маршрут или query-параметр с фикстурами — **последний вариант**: это правка production-приложения, требует такого же согласия, как новая зависимость на Android, и не должна доезжать до прода включённой.

```ts
test('profile card', async ({ page }) => {
  await page.route('**/api/profile', r => r.fulfill({ json: LONG_NAME_FIXTURE }))
  await page.goto('/profile')
  await expect(page).toHaveScreenshot('profile.png', {
    animations: 'disabled',
    mask: [page.locator('[data-testid="timestamp"]')],
  })
})
```

- Baseline пишется `--update-snapshots`.
- Тёмная тема — отдельный проект с `colorScheme: 'dark'`; крупный шрифт — проект с увеличенным корневым `font-size`.
- Снятые PNG лежат рядом с тестом (`*-snapshots/`) — их и открывать через `Read`.

**Разъезд платформ.** Baseline, записанный на локальной машине, почти наверняка не совпадёт с CI (шрифты и рендеринг ОС различаются). Baseline для CI записывается в том же Docker-образе, что и прогон; локальный снимок — рабочий материал для глаз агента, а не эталон в репозиторий.

**Динамика маскируется** — время, счётчики, случайные аватарки, анимированные плейсхолдеры: `mask`, фиксированные фикстуры, замороженное время.

## Статичный макет без приложения

Проверить композицию можно и без проекта. Сюда же — превращение эталона в картинку: HTML-выгрузка claude-design или экспорт Figma сами по себе `Read`'ом не смотрятся, их надо отрендерить в PNG. Тем же способом `@design-expert` снимает свой разовый прогон. Playwright открывает локальный файл и снимает его на нужных ширинах:

```ts
await page.goto('file:///<путь>/mockup.html')
await page.setViewportSize({ width: 390, height: 844 })
await page.screenshot({ path: 'mockup-390.png', fullPage: true })
```

Тёмная тема — `colorScheme: 'dark'` в контексте, крупный шрифт — увеличенный корневой `font-size` через `addStyleTag`. Прототип и его снимки живут в scratch-каталоге сессии и в репозиторий не уезжают.

## Storybook

Если в проекте есть Storybook, состояния компонента уже описаны сториз — снимать удобнее с них (story = состояние = снимок), чем поднимать страницу целиком. Отдельный платный визуальный сервис ради этого не заводить без запроса пользователя.

## Compose Multiplatform в браузере (wasmJs)

UI рисуется в `<canvas>`, DOM-дерева нет: `getByRole` / `getByText` / `getByTestId` не работают. Доступны только координатные клики, assert'ы по console-логам, `window.location.hash` и сам скриншот canvas'а.

Практический вывод: вёрстку общего кода дешевле проверять Roborazzi на Android-таргете, а браузерный прогон оставлять для того, что бывает только в вебе, — загрузка ресурсов, кэш, размер canvas, поведение при ресайзе окна.
