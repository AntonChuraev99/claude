# Изменения в харнессе `~/.claude`

Харнесс ставят другие люди из GitHub. Поэтому у него стандартный open-source флоу: **issue — для того, что не чиним сейчас; PR — для любой правки**. Человеческая версия правил — `CONTRIBUTING.md` в корне репо, держать их согласованными.

## Правка → только PR

1. Ветка от свежего `origin/main` через `EnterWorktree` (CLAUDE.md → «Защищённая ветка и worktree»). Коммит и push в `main` запрещены — и автору, и агенту.
2. Новый файл — сразу `!`-строка в `.gitignore` (whitelist), иначе git его не видит. Проверка: `git check-ignore -v <файл>` печатает `!`-правило.
   Правка, которая должна подействовать в текущей сессии, может идти в живом checkout (исключение CLAUDE.md), но коммит всё равно уходит веткой и PR.
3. Правка `CLAUDE.md`, `rules/`, `agents/`, `skills/`, `model-overlays/`, settings → запись в `improvements/` + строка в index (`improvements/README.md`).
4. Анти-утечка — CLAUDE.md → «Публичный репозиторий»; pre-commit не обходить.
5. Коммит — `/commit`; PR — `/task-gate` Step 6 (`gh pr create --base main`, squash-merge после подтверждения; дифф только из `docs/`, `improvements/`, корневых `README.md`/`CONTRIBUTING.md` — без подтверждения, `references/mr-merge.md` → «Без подтверждения»). В теле PR — `Closes #N`, если правка закрывает issue.

## Не чиним сейчас → issue

Дефект харнесса вне scope текущей задачи, отложенная правка, идея — **issue в `AntonChuraev99/claude`**, а не `// TODO`, не строка в чате и не новая запись в `docs/backlog/` (существующие записи там остаются до разбора).

1. Сначала поиск дубля: `gh issue list -R AntonChuraev99/claude --search "<ключевые слова>" --state all`. Дубль есть — комментарий к нему, не новый issue.
2. Создать по шаблону `.github/ISSUE_TEMPLATE/`:
   ```bash
   gh issue create -R AntonChuraev99/claude --label bug \
     --title "<компонент>: <симптом>" --body-file <scratchpad>/issue.md
   ```
   Идея или улучшение — `--label enhancement`. Тело: что сработало (хук/агент/скилл), ожидание vs факт с точным текстом ошибки, шаги репро, окружение.
3. Тело issue публичное — те же правила анти-утечки: проект → `<your-project>`, путь → `~/...`, без ID и токенов.
4. Ссылку на issue — в отчёт задачи. TODO в коде харнесса допустим только с якорем `// Issue: <url>`; гейт 2.8 считает такой TODO обеспеченным.

Пользователь сказал «не заводи» или «почини сразу» — делать как сказано.

## Чужой PR

Ревьюить как свой дифф: анти-утечка, `.gitignore`-строки для новых файлов, запись в `improvements/` при правке правил, лимит `CLAUDE.md`. Мержит только автор репо.
