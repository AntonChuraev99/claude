# Как писать субагента

Определение субагента — не эссе о специальности, а контракт: что агент видит, чего не трогает, что обязан вернуть и чем докажет, что работает.

## Frontmatter — официальные поля

```yaml
---
name: feature-expert                   # имя, по нему @-упоминание
description: <когда вызывать + DO NOT use>   # по нему Claude решает делегировать
tools: Read, Grep, Glob, Edit, Write, Bash   # allowlist; чем уже, тем лучше
model: opus                            # opus | sonnet | haiku | fable | inherit
effort: high                           # low | medium | high | xhigh | max — бюджет рассуждения
memory: user                           # user | project | local — своя база знаний агента; дока советует project, но для ~/.claude/agents/ верен user
skills: material-3-skill, edge-to-edge # полностью препоадятся в контекст агента
color: green
---
```

Полный набор полей на Claude Code 2.1.x: `name`, `description`, `tools`, `disallowedTools`, `model`, `effort`, `permissionMode`, `maxTurns`, `skills`, `mcpServers`, `hooks`, `memory`, `background`, `omitClaudeMd`, `isolation`, `color`, `initialPrompt`, `experimental.cacheTtl`.

- **`effort`** — режет бюджет рассуждения, не трогая модель. Ставится каждому агенту осознанно: исполнение по готовой процедуре и сбор данных — `low`; реализация по готовой спеке или контракту — `medium` (Opus 5.5 на `medium` в кодинге не хуже Opus 5 на `high`; гипотеза с replay — improvements `2026-10-12-opus-5-5-prompt-audit`); проектирование архитектуры, выбор решения, платформенная отладка, суждение «настоящая находка или ложная» — `high`. Это правильный рычаг там, где раньше тянуло понизить модель: качество модели остаётся, платит только длина размышления.
- **`experimental.cacheTtl`** (`"5m"` | `"1h"`) — субагент живёт в отдельном cache-бакете и **не наследует TTL материнской сессии**. Глобально это решается ключом `subagentPromptCacheTtl` в `settings.json`; per-agent поле нужно, только чтобы отклониться от него. Учти: 1h-записи в кеш билятся дороже, а при overage подписки «1h» игнорируется.
- **`maxTurns`** соблюдается с v2.1.246 (дока `code.claude.com/docs/en/sub-agents`, сверено 2026-09-15): по исчерпании агент останавливается, а результат помечается как partial. Это рабочий рычаг против turn-explosion — жёсткий cap («≤3 git-вызова», «≤N turns») ставить полем, а не только текстом в теле.
- **`omitClaudeMd: true`** (v2.1.271+) — агент не получает иерархию CLAUDE.md. Для агента, который всё нужное берёт из брифа (верификатор, форматтер, исполнитель по готовому пакету), это экономит контекст на каждом вызове и убирает соблазн «исследовать» по правилам проекта вместо фактов из брифа. Специалисту, который пишет прод-код, CLAUDE.md нужен — поле не ставить.
- **`effort` на Haiku** — в таблице поддержки уровней effort (`code.claude.com/docs/en/model-config`) Haiku отсутствует; поле на `model: haiku` дисциплины не добавляет, рассчитывать на него нельзя.
- **`skills` — не механизм ленивой загрузки:** содержимое перечисленных скиллов инъектируется целиком при каждом старте агента. По стоимости это то же самое, что вписать текст в тело. Ленивое — только указатель в теле плюс `Read` по требованию.

- **`description` — самое важное поле.** По нему и только по нему модель решает, делегировать ли сюда. Пишем: когда вызывать (конкретные триггеры и формулировки задач) + **`DO NOT use for:`** с явным перечислением, куда уходят соседние случаи. Расплывчатое описание = агент срабатывает не на те задачи или не срабатывает вовсе.
- **`tools`** — только необходимое. Ревьюер без `Edit`/`Write` физически не сможет «заодно поправить». **Тело ссылается на скилл — `Skill` обязан стоять в `tools`**: без него инструкция «вызови скилл X» мертва, агент её молча пропустит. Агент ищет по коду — нужен `Bash` (через него идёт `ast-index`).
- **`memory`** — включает агенту собственную базу знаний. Накопленный опыт живёт там, а не в теле промпта.
- **`skills`** — препоад: содержимое перечисленных скиллов целиком уезжает в контекст агента при запуске. Класть 1-2 действительно обязательных; остальное агент подтянет сам через Skill tool.

## Когда субагент не нужен

Субагент оправдан, когда работа порождает verbose-вывод, не нужный в основном контексте (чтение сотни файлов, прогон ревью), и её вход **целиком передаётся брифом**. Если же результат зависит от того, что знает только главный — почему выбрали это решение, что провалилось, какой замер был, — субагент вынужден реконструировать, и реконструкция выглядит как факт. (прецедент `doc-writer-dissolve` в `references/claude-md-precedents.md`) Правило: **писать по чужому контексту — не работа субагента; проверять написанное детерминированно — работа хука, а не второго агента.**

## Скелет тела — шесть блоков

```markdown
## Перспектива
<Чем этот агент смотрит на задачу и чего он принципиально не видит.
Не «Ты опытный senior-инженер с 10 годами опыта» — а какой угол зрения.>

## Скоуп
Делает: <2-5 пунктов конкретной работы>
Не делает: <что уходит соседям> → `@<агент>`
Задача упирается в чужой скоуп → `STATUS: NEEDS_DELEGATION <agent>`, не «по краю».

## Что должно прийти в брифе
<Без чего работа невозможна: контракт API, DESIGN_SPEC, пути, APPLY/PITFALLS.
Не пришло — вернуть `STATUS: NEEDS_INPUT`, а не додумывать.>

## Метод
<3-6 шагов, специфичных ИМЕННО для этого агента.
Общие правила из CLAUDE.md не пересказывать — субагент грузит их сам.
Шаг impact scan формулируется через ast-index — см. «Поиск по коду» ниже.>

## Что вернуть
<Жёсткие поля ответа: список изменённых файлов, риски, что проверить главному,
опционально actionable patches. Формат — не «подробный отчёт», а перечень полей.>

## Чем докажешь
<Проверка, дающая pass/fail: тест, компиляция, скриншот, команда с ожидаемым выводом.
Агент, который не может себя проверить, отдаёт непроверенную работу главному.>
```

## Поиск по коду — `ast-index`, не широкий Grep

Любой агент, который ищет символы, использования, реализации или зависимости, делает это через `ast-index` — структурный индекс (SQLite + FTS5), на порядок быстрее Grep и возвращает не строки, а символы с их связями. Формулировка для блока «Метод», одна и та же во всех агентах:

> Ищи через `ast-index` (`search`, `symbol`, `class`, `usages`, `refs`, `implementations`, `callers`, `outline`, `deps`) — структурно и на порядок быстрее Grep. Индекс держит плагин-хук, `rebuild`/`update` не запускать. `Grep`/`Glob` — только когда индекс вернул пусто, нужен regex, строковый литерал, текст комментария или файл вне индекса.

Что кладётся в хвост «файл вне индекса» — зависит от стека агента: Android → `*.gradle.kts`, `*.xml`; Web → `*.css`, `*.json`; wasmJs → `index.html`, service worker. Перечислять явно, иначе агент решает по наитию.

**`rebuild` и `update` агенту запрещены** — это тяжёлые операции, индекс обновляет хук плагина на каждом Edit/Write и на старте сессии. Агент, который начинает работу с `ast-index rebuild`, съедает минуты на пустом месте.

**Само по себе это правило не работает:** в режиме `bypassPermissions` системная подсказка велит обратное («читай через `cat`, ищи через `grep`»), а плагинная напоминалка ast-index висит на matcher `Grep` и вызовов через Bash не видит. Поэтому текстовый поиск по исходникам через Bash **денаится** хуком `hooks/bash-tool-discipline.js` с готовой заменой в тексте отказа. Текст в агенте — третий слой, не первый.

## Цена инструмента — в блок «Метод» каждого агента

**Правило остаётся в теле агента, обоснование — нет.** Это единственное исключение из запрета «пересказ `CLAUDE.md`» ниже, и оно узкое: `CLAUDE.md` субагент грузит сам (кроме агентов с `omitClaudeMd: true` — им нужное кладётся в тело), поэтому в агенте дублируется только императив, а замеры, пороги хуков и объяснения — не дублируются. Резидентного правила здесь оказалось мало (прецедент `shell-latency-bash-completion`). Формулировка (~430 символов — держать в этих пределах, длиннее не дописывать):

> **Цена инструмента.** Нативные тулы вместо Bash-аналогов: файл — `Read`, текст — `Grep`/`Glob`, символы — `ast-index`, правка — `Edit`/`Write`. Bash оставь сборке, тестам, git, `ast-index` и CLI; команды склеивай `&&`, независимые вызовы шли одним сообщением, ждать — `Monitor` или `run_in_background`. Между вызовами не пиши прозу — рассуждение идёт в финальный отчёт. Замеры и границы запретов (их держат хуки) — `CLAUDE.md` § «Цена вызова инструмента».

Развёрнутую версию блока **не восстанавливать**: она оплачивается дважды — вместе с `CLAUDE.md`, который приезжает в каждого не-fork субагента автоматически; если кажется, что короткой мало, правится `CLAUDE.md` или хук, а не тело агента.

## Чего в агенте быть не должно

| Не класть | Почему | Куда |
|---|---|---|
| Пересказ `CLAUDE.md` и правил | субагент грузит `CLAUDE.md` и `~/.claude/rules/` сам (подтверждено докой `code.claude.com/docs/en/sub-agents` — иерархия CLAUDE.md приезжает в каждый не-fork субагент) — это мёртвые токены | удалить |
| — исключение | **императив** правила, которое резидентно не сработало и подпёрто хуком: «Цена инструмента» и «простой тест на свой код пишешь сам». Дублируется только формулировка «что делать / чего нельзя», без замеров, порогов и закрытых списков — они остаются в `CLAUDE.md` за ссылкой на секцию | — |
| Прецеденты вида «баг 2026-04-28 в фиче X» | опыт прошлых задач раздувает промпт и стареет | `agent-memory/` (поле `memory:`) |
| — исключение | прецедент **одной строкой в скобках**, объясняющий, откуда взялся жёсткий запрет («cap ≤3 git-вызова», «не коммитить»), остаётся: без причины запрет читается как каприз и обходится | — |
| Структуры каталогов и паттерны конкретного проекта | user-level агент применяется во **всех** проектах | проектный `.claude/agents/` либо skill с `paths:` |
| Персона: «ты senior с большим опытом» | над-ограничение персоной слабее явной перспективы | блок «Перспектива» |
| Длинные листинги кода как иллюстрация | тело агента — не учебник | skill или `agent-memory/` |
| Общий протокол специалиста | дублируется в каждом агенте | `CLAUDE.md` — там роль главного и границы делегирования |

**Объём — два бюджета сразу: 60-120 строк И ≤11 000 символов тела** (тело = файл без frontmatter). Больше 150 строк или больше 13 000 символов — почти наверняка внутри лежит что-то из таблицы выше, это блокер. Тело между 11 000 и 13 000 допустимо, когда остаток — закрытые списки и платформенные инварианты, обязанные срабатывать всегда, а справочное уже вынесено; правка такого агента начинается с поиска выносимого, а не с подрезки «чтобы влезть».

**Строчный бюджет слеп сам по себе:** плотность строки у агентов доходит до 150-250 символов, и файл в 100 строк бывает в 1.5-2× над подразумеваемым объёмом. Меряй обе величины: `wc -l` и длину в **символах** (не байтах — на кириллице `wc -c` завышает ×~1.6).

Кто сейчас над бюджетом — показывает скрипт из «Проверка после правки», а не список в этом файле. Правка такого агента — сначала перечитать, что именно осталось, и резать только выносимое, а не «чтобы влезть».

Меньше 60 строк — проверь, все ли шесть блоков заполнены содержательно; сам по себе компактный агент дефектом не является. Замер по 15 переписанным определениям (2026-08-03) дал 60-87 строк при полном наборе блоков — нижняя граница не повод дописывать воду.

**`description` — отдельный бюджет, и он резидентный:** все описания набора едут в системный промпт главного каждую сессию. Anthropic предупреждает при сумме >15 000 токенов. Держи описание в пределах ~1 500 символов, а поведенческие инструкции, которые дословно есть в теле, в него не дублируй — но **триггеры вызова и границы `DO NOT use for:` не сокращай никогда**: по ним главный решает делегировать, и тело он при этом ещё не видел.

## Чеклист приёмки

1. `description` называет и триггеры, и границы. Фрагмент пишется английским литералом **`DO NOT use for:`** — по нему идёт проверка грепом; русское «DO NOT use для» её не проходит.
2. `tools` — минимальный набор; у ревьюеров и скаутов нет `Edit`/`Write`.
3. Тело укладывается в шесть блоков, посторонних разделов нет.
4. Нет ни одного упоминания конкретного проекта, если агент лежит в `~/.claude/agents/`.
5. Есть блок «Что вернуть» с перечисленными полями.
6. Есть блок «Чем докажешь» с проверкой, дающей pass/fail.
7. Границы взаимны: если A отправляет случай к B, у B в `description` этот случай упомянут — и B его действительно принимает, а не отводит обратно.
8. Адресат маршрутизации назван по имени (`@feature-expert`), а не плейсхолдером («код-эксперты», `<code-expert>`): по плейсхолдеру взаимность не проверяется и делегирование не срабатывает.
9. Объём в пределах 60-120 строк **и** ≤11 000 символов тела (до 13 000 — только по исключению из «Объём» выше) (символы — скриптом из «Проверка после правки», не `wc -c`).
10. Тело упоминает скилл → `Skill` есть в `tools`. Обратное тоже проверять: `Skill` в `tools` без единого вызова в теле — либо забыли триггер, либо инструмент лишний.
11. Шаг поиска по коду сформулирован через `ast-index`, `Grep`/`Glob` названы как fallback с перечисленными случаями. Агент, который ищет только Grep'ом, — блокер.
12. `background: true` + право `Edit`/`Write` в проектный репозиторий → в «Скоупе» есть проверка защищённой ветки перед первой записью. PreToolUse из `settings.json` на фоновых агентах срабатывает (транскрипт 2026-10-08, `hook_success`; code.claude.com/docs/en/sub-agents), но `protected-branch-guard` — deny-once: повтор того же вызова проходит, и Bash-запись он не видит вовсе. Поэтому правило держится на тексте агента.
13. `effort` проставлен осознанно (`low` — исполнение по процедуре, `high` — проектирование и суждение), а не скопирован у соседа.
14. Тело не утверждает про свои инструменты того, что рантайм опровергает. Частый случай: `memory: user` возвращает агенту `Edit`/`Write` поверх `tools:`-allowlist'а, и фраза «`Edit`/`Write` у тебя нет» становится ложной — read-only держится **контрактом**, и писать надо именно так.
15. Каждая названная в теле команда, скилл и агент существуют. Проверять на месте: скиллы — по листингу сессии (плагинные зовутся с префиксом, `frontend-design:frontend-design`, голое имя не проходит), команды — `ls ~/.claude/commands/`, агенты — по реестру. Мёртвый адресат хуже отсутствующего: маршрут выглядит рабочим.
16. Терминология не протухла. Классификация задач `Trivial/Standard/Complex` и оси `complexity`/`impact` **упразднены 2026-08-03** — в новых и правленых агентах их быть не должно.

## Вынос справочника в `references/` — что делает указатель рабочим

Вынесенное читается не всегда: прецедент `clauderules/` — самодельный lazy-каталог не открывался вовсе. Разбор рабочего образца (2026-09-01, `agents/google-play-console-expert/`) дал три условия, и они действуют **только вместе**:

1. **Абсолютный путь и точные имена файлов**, а не «см. справочник». Агент не ищет — он открывает.
2. **Условие в императиве плюс запрет, невыполнимый без чтения:** «флаги по памяти не воспроизводить», «цифру по памяти не называть». Мягкое «подробности в файле» даёт ровно тот отказ, ради которого правило и писалось. Формулировка «причины — в файле» не работает: у агента нет вопроса «почему», и он не откроет.
3. **Инлайн-минимум, переживающий неоткрытый файл:** в теле остаётся сам запрет или инвариант, в файл уходят детали. Тогда «агент не открыл» деградирует до «агент знает правило, но без деталей», а не до «агент правила не знает».

**Что не выносить:** жёсткие запреты, границы делегирования, «Что вернуть», «Чем докажешь», а также каталог, по которому агент вообще узнаёт о существовании возможности (таблица скиллов: не открыв файл, он не вызовет ни одного). Выносить хорошо: числовые снимки, которые и так требуют перепроверки в первоисточнике, платформенные лимиты, длинные чеклисты, механику, нужную по условию.

**Куда выносить.** `~/.claude/references/` — если справочник не содержит приватного (он трекается git и уезжает в MR вместе с правкой). `agent-memory/<agent>/` — если содержит имена проектов, ID, внутренние детали: этот каталог gitignored и в репозиторий не попадёт. Один предмет — один адрес: два лениво-загружаемых хранилища на одну тему расходятся между собой.

## Проверка после правки

```bash
wc -l ~/.claude/agents/*.md          # строчный бюджет (60-120)
grep -c "DO NOT use" ~/.claude/agents/<name>.md   # description содержит границы
grep -L "ast-index" ~/.claude/agents/*.md         # кто ещё ищет вслепую
```

Символьные бюджеты — только так (`wc -c` на кириллице врёт ×~1.6):

```bash
python -c "
import glob
for f in sorted(glob.glob('$HOME/.claude/agents/*.md')):
    s=open(f,encoding='utf-8').read(); p=s.split('---')
    body='---'.join(p[2:])
    print(f\"{f.split('/')[-1]:<30}{len(body):>7} тело\")
"
```

Плюс сверка Skill-консистентности — тело зовёт скилл, а инструмента нет:

```bash
for f in ~/.claude/agents/*.md; do
  body=$(tail -n +10 "$f")
  echo "$body" | grep -q 'Skill(skill=' && ! grep -q '^tools:.*Skill' "$f" && echo "BROKEN: $f"
done
```

Плюс прогон на реальной задаче: сформулировать запрос, который **должен** попасть в этого агента, и запрос, который должен уйти соседу, — и посмотреть, куда уходит делегирование.
