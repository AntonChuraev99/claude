# Документ задачи — пишет главный

Факты документа — почему выбрали это, что провалилось, какой замер был — живут только в контексте того, кто делал задачу. Писатель со стороны получает дифф и бриф и вынужден реконструировать «почему» — так и рождались выдуманные сигнатуры и замеры. Поэтому документ пишешь ты, из своего контекста, а машина проверяет только то, что проверяется машиной: имена, пути, ссылки, числа.

Признаки, при которых документ обязателен, — `CLAUDE.md` → «Документирование»; судятся по факту диффа. Структура `docs/`, жизненный цикл, `todos` vs `backlog` — `~/.claude/rules/docs-structure.md`.

## INIT — стаб на старте задачи

Одна `Write`, когда признак документирования уже виден или ожидаем (на INIT известны не все — это нормально; не сработал ни один → стаб не нужен, на COMPLETE он реконструируется из диффа).

1. Проверить `docs/active/` **и** `docs/archive/` на документ этой же задачи. Похожий активный — использовать. Похожий в архиве (задачу возобновили) — вернуть `mv` в `active/`. Дубль не создавать.
2. `git rev-parse HEAD` → Start SHA (не git — `none`); project slug — basename `git rev-parse --show-toplevel`.
3. `docs/active/<slug>-<YYYY-MM-DD>.md`, slug — 3-5 слов kebab-case. Шаблон шапки и секций — `references/templates.md` → «Документ задачи».

Ветку проверяет `protected-branch-guard`: первый `Write` в транке заблокируется с текстом правила, отдельной проверки не нужно.

## Итерация — одна строка после возврата специалиста

Хук `hooks/iteration-log-reminder.ps1` напоминает после каждого специалиста. Действие — одна `Edit`: под `## Лог итераций` строка

```
### Итерация N — <дата> — <агент>: <что сделано> → <результат>
```

Развёрнутый блок («Почему так», «Баги», «Решение») — только когда итерация объясняет выбор: провалившаяся гипотеза, смена подхода, найденный корень бага. Успешный шаг по плану — одна строка. Тут же сверить `## Технический план`: разошёлся с фактом — исправить пункт, причину отметить строкой. Промежуточный итог писать как `**Итог итерации:**`, не `**Статус:**` — SessionStart-дайджест берёт статус из шапки, второй `Статус:` в теле его собьёт.

## COMPLETE — на `/task-gate` 2.4

1. **`## Выводы`** — по факту: что делали, что выяснили, что осталось. Без вводных оборотов и оценок важности. В шапку `**Статус:** Done`; `Partially Done` / `Deferred` — тоже честный статус, такой документ остаётся в `active/`.
2. **Нужен ли постоянный документ.** Знание переживает задачу → да: решение технической проблемы или workaround → `docs/solutions/<slug>-<date>.md`; архитектурное или продуктовое решение → `docs/decisions/<slug>-<date>.md`. Переиспользовать нечего — постоянного документа нет, это нормальный исход. Шаблон, правила `keywords:`, секции для fix-after-deploy — `references/templates.md`; потолки длины — `~/.claude/references/doc-length-budget.md`, по памяти не воспроизводить.
3. **Источники — правило каждого факта.** Идентификатор, сигнатура, путь, строка стектрейса — открыть файл и вставить дословно; по памяти не восстанавливать даже то, что «точно помнишь». Число — только из вывода инструмента в этой сессии, и в той же строке `источник: <команда, чарт, лог>`; иначе `(приблизительно)` или не писать вовсе. Команда или конфиг, который не запускал, — `(не проверено)`. Источник недоступен — `TODO: сверить с <файл>`, не правдоподобный сниппет. Механизм («X зовёт Y при Z») — только то, что видел в этой задаче сам.
4. **Проверка фактов — обязательно, до архивации:**

   ```
   node ~/.claude/hooks/docs-facts-guard.js <solution.md> <active.md> --base <BASE_SHA>
   ```

   Каждую претензию закрыть: имя — исправить по файлу либо `TODO: сверить`; ссылку — только исправить (маркер её не закрывает); путь — исправить, а вне репозитория — `(не проверено — <почему>)`; число — `источник:` в строке либо `(приблизительно)`; внешний флаг, SDK, чужой репозиторий — `источник:` или `(не проверено — <почему>)`. `LINK` и `PATH` в нуле обязательно — в gate они блокер. С `--base` скрипт отчитывает только претензии, которых не было в версии документа на базе задачи. Хук срабатывает и на `Write` в `docs/{solutions,decisions,archive}/` — его вывод читать, а не листать.
5. **INDEX.** Строку наверх таблицы `docs/solutions/INDEX.md` (шапку и счётчик — только если файл не под `merge=union`, правило в `rules/docs-structure.md`). Формат — `references/templates.md` → «Строка INDEX».
6. **Архив.** `## Лог итераций` схлопнуть до одной строки на итерацию (развёрнутыми остаются только объясняющие выбор), затем `mv docs/active/<f> docs/archive/<f>` — только при `Done`. Без `git add` / `git mv`: стейджит `/commit`. `Glob` подтвердить, что файлы лежат там, где отчитался.
7. **`## Предложения по улучшению агентов`** — из собственных наблюдений за специалистами в этой задаче: паттерн, которого в агенте нет, антипатерн, о котором он не предупредил, версия API, которую он не знал. Нет — секция остаётся пустой. `/task-gate` Step 4 читает её отсюда.

## Что отдать gate

- `DOCS_WRITTEN: <репо-относительные пути через запятую | none>` — по ней 2.7b сверяет, что документы уехали в тот же коммит, что и код.
- `ARCHIVED: <путь>` — при переносе в `docs/archive/`.
- Строку статистики задачи пишет сам gate (2.6) из `Шагов: N` и диффа — отдельно её не собирать.

## Чем докажешь

`docs-facts-guard` по всем написанным файлам — `TOTAL: 0`, либо каждая оставшаяся строка закрыта маркером с причиной · заголовки секций по-русски дословно как в шаблоне (`## Решение`, не `## Solution` — по ним грепает следующий агент) · `Glob` показывает файлы по отчитанным путям · строка в `INDEX.md` есть, если есть постоянный документ.
