# improvements/ выведен в публичную часть с отсечкой

## Цель

Каталог `improvements/` был целиком gitignored, а правки харнесса едут в репозиторий через MR. Запись об улучшении физически не могла попасть в тот же MR, что и правка: она оставалась в рабочем каталоге и жила отдельно от истории, которую объясняет. На предыдущей задаче это вскрылось буквально — запись пришлось переносить руками из worktree до его удаления, иначе она исчезла бы вместе с каталогом.

## Baseline (до изменений, на дату 2026-08-26)

- `improvements/` не в whitelist `.gitignore` (стратегия каталога — `*` игнорирует всё, `!`-строки возвращают разрешённое), то есть невидим для git целиком.
- **197 записей**, из них **97 (49%)** содержат данные, которые anti-leak pre-commit хук блокирует: имена приватных проектов, числовые ID аналитики и облака, личные пути, почта. Замер — прогон паттернов хука по каталогу.
- **357 упоминаний** имён приватных проектов суммарно; распределение неравномерное — три проекта дают более 90%.
- Записи писались в расчёте на приватность: имена проектов в них не обобщены, потому что обобщать было незачем.

## Гипотеза

Публиковать каталог целиком нельзя без чистки 97 файлов, а чистка задним числом дорога и меняет исторические записи. Но цель — не публичная история улучшений, а **доставка новой записи в MR**. Значит достаточно отсечки: всё написанное до неё остаётся приватным архивом, публикуется только то, что пишется уже по правилу анти-утечки.

## Изменения

**1. `.gitignore` — правило 7d2.** В whitelist добавлены `!/improvements/` и `!/improvements/*.md`, следом `/improvements/archive/` возвращает архив в игнор (в git побеждает последнее совпавшее правило). Проверено `git check-ignore -v`: корневой README не игнорируется, файл в `archive/` игнорируется правилом архива.

**2. Физическая раскладка (вне git).** 195 записей перемещены в `improvements/archive/` (плюс два месячных сводных архива, уже лежавших там); среди перемещённых — одна сегодняшняя запись, не прошедшая проверку на приватные имена. В корне остались README и две сегодняшние записи, чистые по паттернам хука. **Граница проведена по происхождению, а не по дате**: «до отсечки» в первой редакции формулировки означало дату, и сегодняшняя приватная запись по букве правила оказывалась публичной — поймано ревью.

**3. Индекс разделён.** Публичный `README.md` переписан: описание системы, шаблон записи, порядок работы, раздел «Публикация и анти-утечка» и таблица **только публичных** записей. Полная таблица 195 архивных записей вынесена в `archive/INDEX.md` — приватный, лежит рядом с записями, на которые ссылается. Добавлен публичный `improvements/ARCHIVE.md`: правила ссылаются на архивные записи путями `improvements/archive/...`, и без пояснения внешний читатель видит битую ссылку рядом с опубликованным каталогом.

**4. `CLAUDE.md`.** В разделе анти-утечки `improvements/` явно назван среди публичных файлов. В разделе «Изменения глобальных правил» добавлено: запись публичная, едет в MR, пишется санитизированной с первой строки, архив до отсечки — приватный.

**5. Impact scan — ссылки на перемещённые записи.** 16 упоминаний путей вида `improvements/<дата>-<slug>` в 10 публичных файлах (`review-rules/*.yaml`, `skills/*/SKILL.md`, `docs/backlog/*`) переписаны на `improvements/archive/...`. Без этого пути указывали бы в пустоту: файл физически переехал.

**6. Дыра в denylist anti-leak хука.** Найдена по ходу замера: имя одного из реальных проектов в denylist отсутствовало, хотя проект есть в реестре защищённых веток. Хук пропустил бы его **108 упоминаний**. Добавлено в живой `.git/hooks/pre-commit` (файл не отслеживается git — правка локальная, в репозиторий не едет). Шаблон `hooks/pre-commit` не тронут: он generic, с плейсхолдерами.

## Что НЕ менялось (сознательно)

- Санитизация архива задним числом — отклонена вместе с вариантом «вынести всё»: 97 файлов правки плюс ручная вычитка, и правки меняют исторические записи, ценность которых в том, что они писались тогда.
- Шаблон `hooks/pre-commit` — остаётся generic.
- Правило «улучшение + строка в index» — формулировка сохранена, изменилось только место индекса для архивных записей.

## Target (к 2026-09-09)

- Каждая задача, менявшая `~/.claude/{CLAUDE.md, rules, agents, skills, settings.json}`, имеет improvements-запись **в том же MR**, что и правка. Проверяется по диффу MR, не по наличию файла на диске.
- Ноль срабатываний anti-leak хука на файлах публичной части — если срабатывает, правило «писать санитизированной сразу» не работает и нужен более явный шаблон.
- Ноль записей, случайно созданных в `archive/` вместо корня.
