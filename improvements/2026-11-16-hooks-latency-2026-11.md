# Хуки: скорость и чистка (ноябрь 2026)

## Цель

Хуки харнесса стали заметной долей ожидания: каждый старт сессии запускал десять процессов, каждая правка — шесть. Под нехваткой памяти процессы стоят до старта, и хуки упираются в таймаут сериями. Цель — меньше процессов на частых событиях, без холостого старта pwsh, и снять плагинный хук, который даёт почти половину таймаутов.

## Baseline (до изменений, на дату 2026-11-16)

- Таймауты хуков за 30 дней: 157 на 1809 транскриптах (источник: `python scripts/hook-timeouts-report.py --days 30`). Из них 73 — `grep-reminder.sh` плагина ast-index (PreToolUse на каждый Grep, bash + jq), 22 — `protected-branch-guard.ps1`, 7 — `guard-claude-work-writes`, 6 — warp `on-stop.sh`, 6 — `review-rules/stop-gate.ps1`, остальные — SessionStart сериями по 15–16 с.
- Холостой старт (источник: замер главного 2026-11-16): pwsh 0,32–0,35 с; node 0,1 с; python 0,1–0,28 с; `protected-branch-guard.ps1` 0,41–0,46 с; `ensure-bash-discipline-registered.ps1` 0,57–0,79 с.
- SessionStart: 10 своих процессов, из них 6 pwsh (два — обёртки: `ensure-hook.ps1` только звал python, `ensure-worktree-guard.ps1` пустой вне worktree).
- Write/Edit: 6 процессов — PreToolUse node + pwsh, PostToolUse node + node + bash (ast-index) + bash (warp).
- Warp-патч не применялся с 2026-10-28: установлена 2.4.0, патч знал версии до 2.3.0. Итог — systemMessage на каждом старте и непропатченный `on-post-tool-use.sh` на каждом вызове инструмента (1,7 с по замеру в коде патча).
- Stop: `stop-gate.ps1` 2236 запусков за 30 дней, 4 уникальные блокировки.
- `notify_debug.log` 16,8 MB, пишется на каждый Stop и Notification без ротации.
- Issue #71: после `/clear` сессия получает оверлей чужой модели из общего кэша профиля.

## Гипотеза

Цена хука на Windows — старт процесса, а не работа: проверки занимают миллисекунды. Объединение хуков одного события в один процесс и перевод с pwsh на node/python убирает 0,3–0,8 с на процесс и снижает шанс упереться в таймаут под подкачкой. Снятие `grep-reminder.sh` убирает самый частый таймаут целиком: тот же Grep уже судит `credentials-guard-prefilter.js` в своём процессе.

## Изменения

- `hooks/ensure-plugin-patches.js` (вместо `ensure-warp-perf-patch.js`): warp — 2.4.0 сверена с 2.3.0 диффом, отличие только в `on-stop.sh` (поля `background_task_count`, `session_cron_count`), `notify.jq` теперь считает их из stdin; payload патча перенесён в репозиторий (`hooks/plugin-patches/warp-perf/`, MIT, NOTICE). ast-index — из `hooks.json` плагина снимается запись `grep-reminder.sh`, остальные хуки плагина не трогаются. На успехе молчит, на неизвестной версии — одна строка.
- Write/Edit: `hooks/write-guards.js` — один PreToolUse-процесс для `guard-claude-work-writes` и `protected-branch-guard.js` (порт с pwsh, вывод совпал с pwsh-версией по значениям на 22 сценариях); `hooks/docs-guards.js` — один PostToolUse-процесс для обеих docs-проверок.
- SessionStart: `hooks/session-start.js` (model-overlay, worktree-подсказка и регистрация гарда worktree, патчи плагинов, проверка bash-discipline) и `hooks/session-start.py` (дайджест docs, лимит CLAUDE.md, `run.py --ensure-hook`). Каждый модуль — в своём try. `model-overlay.js` — порт с pwsh плюс кэш модели по session_id и cwd (#71). Причина #71 — не два профиля (кэш уже был на `CLAUDE_CONFIG_DIR`), а параллельные сессии одного профиля. Остаток: две сессии в одном каталоге с разными моделями пересекутся на `/clear`, если `/clear` выдаёт новый session_id (не проверено — нужен живой прогон). Логика `ensure-worktree-guard.ps1` — в `worktree-bash-hint.js`, как раньше только на SessionStart: гард, зарегистрированный на EnterWorktree, действует лишь после рестарта и печатал бы предупреждение на каждом новом worktree. Проверка bash-discipline и лимит CLAUDE.md — в процессе агрегатора без кэша: работа стоит миллисекунды, а вынос в pre-commit не покрыл бы проектный CLAUDE.md и живой `settings.json`.
- Дайджест в репозитории харнесса добавляет строку при ≥10 просроченных replay.
- Stop: `run.py --stop-gate` вместо `stop-gate.ps1`. Повтор того же состояния дерева в той же сессии пропускает проверку. Состояние учитывает размер и mtime неотслеживаемых файлов: иначе правка внутри такого файла не меняла бы хэш. Маркер ack лежит в git-dir, поэтому в linked worktree он теперь работает.
- `notify.ps1`: трассировка только при `CLAUDE_NOTIFY_DEBUG=1`, строки ошибок пишутся всегда, ротация на 1 MB. Удалён неиспользуемый `hooks/log-incident.js`.

## Target

- Таймауты хуков за 14 дней после внедрения: ≤ 25 (против ~73 за 14 дней в baseline-темпе), строк `grep-reminder.sh`, `branch guard`, `guard: .claude-work` в отчёте — 0.
- Свои процессы: SessionStart 10 → 4, SubagentStart 3 → 2, Write/Edit 6 → 4 (2 своих + 2 плагинных bash).
- Нет systemMessage warp-perf-patch на старте; нет повторов #71.
