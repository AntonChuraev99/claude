# Скиллы setup и harness-doctor

## Цель

Настройка проекта под харнесс была ручной и неполной: CLI ставились по факту
ошибки, проект попадал в реестры веток и кредов не всегда, `.worktreeinclude`
дописывался после упавшей сборки в worktree. Конфликты глобального CLAUDE.md с
проектным никто не проверял: противоречие видно только по странному поведению
агента.

## Baseline (2026-11-24)

Прогон `doctor.py` без `--fix` по двум проектам и харнессу:

- 3 из 3 — хотя бы один fail (gitignored-конфиг вне `.worktreeinclude` — в обоих
  проектах; нет `gitleaks` для харнесса);
- в реестрах веток и кредов — по 3 пути, которых нет на диске;
- проектный CLAUDE.md выше порога размера — 2 из 2 проектов;
- смысловые конфликты инструкций — не измерялись.

## Гипотеза

Один скрипт с проверками и починкой плюс смысловой разбор агентом закрывают
механические поломки за один прогон, а явные исключения вместо молчаливых
противоречий убирают «плавающее» поведение агента в проекте.

## Изменения

- `skills/harness-doctor/` — SKILL.md и `scripts/doctor.py` (машина, харнесс,
  проект, механические конфликты, список источников инструкций; `--fix` чинит
  сразу, реестры — с копией `*.bak-doctor`), `scripts/doctor.tests.py`.
- `skills/setup/SKILL.md` — разведка → вопрос про аккаунт → `doctor.py --fix` →
  правки файлов проекта через worktree → `harness-doctor`.
- `CLAUDE.md` — исключение к запрету `ast-index rebuild`: индекса нет — скилл `setup`.
- Имя `harness-doctor`, а не `doctor`: встроенная команда `/doctor` Claude Code.

## Target

К 2026-12-08: по всем проектам реестра `doctor.py` без `--fix` — 0 fail, кроме
`manual`; хотя бы один прогон `harness-doctor` с найденным и исправленным
смысловым конфликтом.
