# Калибровка под Opus 5.5

## Цель
Opus 5.5 вышла 2026-09-22. Нужно сверить правила с официальными гайдами Anthropic и убрать то, что под новую модель вредит.

## Baseline (до изменений, на дату 2026-09-23)
- `hooks/model-overlay.ps1`: id `claude-opus-5-5[1m]` уходил в `opus-5.md` (оверлей Opus 5, дефолт effort `high` — для 5.5 неверно). Payload без `model` (SessionStart на `/clear`) уходил в `opus.md` — оверлей Opus 4.8. Проверено ручным запуском хука; сессия этой задачи сама стартовала с оверлеем 4.8.
- Потолок субагентов «2-4 одновременно, без вложенности» держался только текстом `CLAUDE.md`; дефолты харнесса — 20 одновременно, глубина 3.
- Доля сессий с неверным оверлеем — нечем измерить: хук не логирует выбор. Лечится строкой лога, если replay покажет нужду.

## Гипотеза
- Кеш последнего id делает оверлей верным после `/clear` и `/compact`, а новейший оверлей как fallback безопаснее Opus 4.8: поведение 4.8 (неохотно делегирует) противоположно 5.x.
- Лимиты харнесса держат потолок субагентов независимо от того, как модель прочтёт текст (Anthropic: инструкция только направляет, лимиты — enforced).
- Self-check через прогоны `/task-gate`, а не через перечитывание, убирает лишний проход, от которого Anthropic предостерегает для 5.x.

## Изменения
- `model-overlays/opus-5-5.md` — новый: база Opus 5 + дельты 5.5 (effort `medium` по дефолту модели, у пользователя сознательно `xhigh`; thinking не выключается; промежуточный текст — progress-update).
- `hooks/model-overlay.ps1` — ветка `*opus-5-5*` перед `*opus-5*` (с `break`: PowerShell `switch` исполняет все совпавшие ветки); кеш id в `<config dir>/model-overlay-last-model.txt` (gitignored, свой на профиль); нет id и кеша → `opus-5-5.md`.
- `hooks/model-overlay.tests.ps1` — +9 кейсов (5.5, кеш, fallback), контракт «нет модели → opus.md» заменён на «нет модели → кеш → новейший»; 28/28.
- `CLAUDE.md` — «Делегирование»: потолок держит харнесс через `env`; «Self-check» — через прогоны гейта.
- `~/.claude/settings.json` (не в репозитории, не проверено хуком — gitignored) — `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS=4`, `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1` (источник: code.claude.com/docs/en/agent-sdk/subagents, «Cap subagent depth, concurrency, and spend»; дефолты харнесса 20 и 3).
- `references/claude-md-precedents.md` — прецедент `opus-5-5-calibration`.
- Принятый компромисс кеша: он пишется только на SessionStart, поэтому `/model X` посреди сессии и затем `/clear` (или две сессии одного профиля на разных моделях) дают оверлей последней стартовавшей модели. Payload лучшего сигнала не даёт; частый случай (та же модель, `/clear`) исправлен.
- Сознательно не тронуто: `effortLevel: xhigh` (решение пользователя); правило про Bash в bypassPermissions (подсказка bypass-режима всё ещё советует обратное).

## Target
- После `/clear` в сессии на 5.5 приходит `opus-5-5.md`.
- Ни одного `Concurrent subagent limit reached` на обычных задачах (4 хватает для скаутов и ревью); ни одного вложенного спавна.
