# ARTEMIS — основной исполнитель проверок на устройстве

## Цель
Снять с Claude пошаговое прокликивание устройства (десятки вызовов `mobile` MCP со скриншотами в контексте) и отдать его дешёвой модели, оставив Claude то, где нужно качество: сценарий по коду экрана и вердикт по артефактам.

## Baseline (до изменений, на дату 2026-09-30)
Проверки шли через `mobile` MCP по `commands/mcp-mobile-test.md`, который к этой дате ссылался на несуществующие имена тулов (`tap`, `assert_visible`, `run_flow` вместо `ui`/`input`/`flow`). Счётчика прогонов и их стоимости нет — нечем измерить; лечится строкой в отчёте каждого прогона («Исполнитель: ARTEMIS … / mobile MCP»), по которой считается replay.

Оценка 2026-09-21 не брала ARTEMIS (Gemini-first, спор об атрибуции). На 2026-09-30: атрибуция частично исправлена (`third_party/mobile_use/` с LICENSE/NOTICE, коммит 2026-09-29), #138 (не-Gemini провайдеры) и #55 (shell-injection через `package_name`/`url`) открыты. Подписку Claude Code ARTEMIS не использует — только API-ключ провайдера (проверено по коду `artemis/llm/router.py`).

## Гипотеза
Качество прогона определяет сценарий, а не исполнитель: если Claude пишет шаги с дословными подписями, проверкой после шага и условием остановки, Flash-модель проходит линейный путь не хуже, а вердикт по скриншотам шагов убирает риск самоотчёта «completed».

## Изменения
- `commands/mcp-mobile-test.md` переписан: ARTEMIS первым (diagnose → сценарий по шаблону → run → Monitor по `status.json` → вердикт по `inspect_trace`), `mobile` MCP — запасной путь с актуальными именами тулов в самой команде; `references/mcp-test-patterns.md` по-прежнему со старыми именами — в команде помечен как источник приёмов, не вызовов (актуализация не заказана).
- Вне репозитория: ARTEMIS в `~/tools/artemis`, MCP `artemis` в обоих профилях (`claude mcp add -s user`), ключ `GEMINI_API_KEY` бесплатного тарифа в его `.env`. Риск: бесплатный тариф Gemini отдаёт запросы и скриншоты на обучение Google — принят пользователем.
- Бесплатная квота `gemini-3.8-flash` (дефолт ARTEMIS) — 20 запросов/сутки на модель (`GenerateRequestsPerDayPerProjectPerModel-FreeTier`); первый прогон исчерпал её ретраями и упал таймаутом 180 с. Локально в `~/tools/artemis/config/artemis.jsonc` дефолт и chunking переведены на `gemini-3.5-flash-lite` → `3.1-flash-lite`. Смоук (Настройки → Батарея → Home, 3 шага) прошёл: 7 запросов, 49 343 входных токена, вердикт сверен по кадрам шагов. Прогон через MCP из сессии Claude Code (Настройки → «О телефоне» → версия Android) остановлен пользователем после проверки связки; по `view_summary` flash-lite за 5 шагов дважды свайпнул и нажал Home, не отчитавшись о прочитанном экране — наблюдение к replay: качество исполнителя на lite-модели, вердикт только по кадрам.
- Установщик ARTEMIS (`artemis mcp --install claude`) не использован: он пишет `~/.claude/rules/artemis.md` без `paths:` (грузилось бы в каждую сессию) — ключевые правила перенесены в команду.

## Target
К 2026-10-14: ≥70% прогонов закрыты через ARTEMIS без отката на `mobile`; сбой исполнителя (не баг приложения) — не больше 1 перезапуска на прогон в среднем. Хуже — вернуть `mobile` основным, ARTEMIS оставить для длинных сценариев.
