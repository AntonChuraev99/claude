# Оверлей Fable 5.1

## Цель
Пользователь перешёл на Fable 5.1. `model-overlays/fable.md` был откалиброван под Fable 5 (2026-07-23): заголовок и текст называли модель «Fable 5», дельты считались от Opus 4.8, а сдвиги 5 → 5.1 из migration guide в нём отсутствовали. Хук `model-overlay.ps1` матчит `*fable*`, поэтому 5.1 уже получала этот файл — механика верна, контент устарел.

## Baseline (до изменений, на 2026-09-03)
- `fable.md`: «Fable 5», 6 дельт от Opus 4.8, 3 пробы n=1 (2026-07-23), помечен light-empirical / не финал.
- Транскриптов Fable (`"model":"claude-fable-5*"`) в `~/.claude/projects` нет — mining-проход по логам (метод из `archive/2026-07-23-model-overlay-hook.md`) невозможен; нечем измерить частоту `AskUserQuestion`, спавнов субагентов и многословности. Лечится накоплением сессий на 5.1.
- Хук-сьют `hooks/model-overlay.tests.ps1`: 20/20 PASS.

## Гипотеза
Anthropic делит гайд на два слоя — Opus → 5.1 и 5 → 5.1 — и второй для оверлея важнее: активная модель уже из семейства Fable, а харнесс Claude Code 2.1.259 на Fable сам инжектит snippets под 5.1 (преамбула и recap, «Delivering work», «Writing for the user», автономность, «не сворачиваться из-за длины контекста»). Значит оверлей должен (а) не дублировать харнесс, (б) нести только 5.1-специфику и (в) явно разводить места, где CLAUDE.md расходится с гайдом, а не молча их инвертировать (урок `2026-08-27-delegation-rule-erosion`).

Сдвиги 5 → 5.1 (источник — bundled-скилл `claude-api`, `shared/model-migration.md` §«Migrating to Claude Fable 5.1» и §«…from Claude Fable 5», `shared/prompt-audit.md` §1d):
- under-communication прогресса на длинных tool-циклах, короче summary;
- whole-file rewrite вместо точечной правки;
- попутные фиксы и test sprawl: на открытой задаче делает запрошенное «и иногда больше» (описание абсолютное, сравнения с 5 гайд не даёт; «реже расширяет scope» vs 5 — заявлено, помечено unverified);
- проза плотнее (mannered prose), форматирования меньше; анти-форматные запреты и повтор инструкции по cadence — fossil-паттерны, вредят;
- параллельная делегация субагентам надёжна, рекомендован non-blocking режим;
- на `low` effort — ответ по памяти вместо поиска для свежих имён;
- safety-классификаторы (cyber, bio, reasoning_extraction, frontier_llm) дают меньше ложных срабатываний, чем у Fable 5 на запуске; три ситуации ложного `refusal` и переформулировка по гайду; редкие early stop и «context anxiety» в очень длинных сессиях.

Перепрогон проб 2026-07-23 на 5.1 (субагент `model: fable`, n=1/проба, без Opus-контроля — сравнение с записанным результатом Fable 5):
- (a) неоднозначный `dedupe(List<User>)` без критерия → действует: взяла `id`, назвала допущение, альтернативы по строке на каждую. Как Fable 5 (итого 3/3 за два прогона).
- (b) переименование `cnt → count` → ровно код, ноль прозы, ~3 с. Как Fable 5.
- (c) ревью функции с одним багом (`0..size` вместо `indices`) → баг найден, generics/vararg нет; но «улучшенная версия» шире, чем у 5: отдельно минимальный фикс и контракт-меняющий редизайн (BigDecimal/Currency/Locale) плюс советы по тестам и KMP. Согласуется с «test sprawl / заодно» из гайда.

## Изменения
- `model-overlays/fable.md` — переписан: заголовок «Fable 5.1»; шапка «что харнесс уже несёт, здесь не дублируется»; блок «Сдвиги 5 → 5.1» (6 пунктов); блок «Профиль Fable, подтверждено на 5.1» (4 пункта с результатами перепрогона); инфо про safeguards и сбои длинных сессий; метод и источники. Явная сверка с CLAUDE.md: правило «без промежуточных реплик» названо гигиеной (прецедент prose-turns-miscount) и согласовано с преамбулой/recap харнесса; потолок субагентов и «прод-код пишет специалист» подтверждены неизменными.
- `CLAUDE.md` → «Цена вызова инструмента», правило «без промежуточных реплик»: в закрытый список исключений добавлена одна строка по требованию харнесса (преамбула перед стартом, ответ на напоминание «the user hasn't heard from you»). По прецеденту `delegation-rule-erosion` конфликт оверлея с CLAUDE.md резолвится в самом CLAUDE.md, а не в оверлее (иначе смысл правила зависит от порядка загрузки файлов) — на это независимо указали оба ревьюера диффа.
- Хук и тесты не менялись: `*fable*` покрывает `claude-fable-5-1`; отдельный `fable-5-1.md` не заводился — Fable 5 superseded, инверсий уровня Opus 4.8 → 5 гайд не фиксирует (единственная — форматирование: 5.1 недоформатирует там, где прежние модели переформатировали).
- Ревью диффа свежим субагентом (порог — доказуемость, сверка с гайдом построчно): 4 находки, все исправлены до коммита — «test sprawl выше, чем у 5» было приписано гайду (он описывает 5.1 абсолютно, относительная часть — только проба c); `docs/todos` → `docs/backlog` (todos — только внешне заблокированное); safeguards — по гайду переформулировка запроса, а не «сказать пользователю»; пункт про прогресс сначала переформулирован как ответ на требование харнесса, затем — после того как gate-ревью 2.3b повторило замечание со ссылкой на прецедент — исключение внесено в сам CLAUDE.md одной строкой.

## Target (к 2026-09-17)
- Fable-сессии видят оверлей 5.1; ложных срабатываний хука нет.
- Наблюдаемое в реальных задачах: точечные `Edit` вместо `Write` поверх файла; попутные баги идут строкой `SUSPECTED_BUG`, а не фиксом в диффе; строка-преамбула и recap есть, прозы после каждого вызова нет.
- Появились транскрипты Fable 5.1 → mining-проход по методу `archive/2026-07-23-model-overlay-hook.md` и Replay.

## Anti-target
- Не переносить в оверлей нейтральные правила CLAUDE.md и snippets, которые харнесс уже инжектит.
- Не расширять исключение CLAUDE.md «без промежуточных реплик» дальше одной строки по требованию харнесса — проза между вызовами по своей инициативе остаётся под запретом.
