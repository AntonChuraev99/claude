# Task gate: артефакт для подтверждения

## Цель

Шаг 5.2 `task-gate` заканчивался строкой «Подтверди результат — дальше сам: push → MR → merge». Подтверждать пользователю предлагалось по таблице статусов и диффу: для web — без запущенного сервера, для Android — без сборки, которую можно поставить на телефон. Проверка сдвигалась на сторону пользователя (собрать, запустить, найти экран), либо результат подтверждался «на веру». Нужно, чтобы отчёт приносил то, что можно открыть и потрогать.

## Baseline (до изменений, на дату 2026-09-14)

- `~/.claude/stats/task-gate-timings.jsonl` — 97 записей, поля про артефакт нет; доля отчётов с localhost/APK/снимками не измерялась. По памяти сессий: localhost поднимался только когда пользователь просил отдельно, APK ставился скиллом `/install-device` по явному вызову, снимки 2.2b шли в таблицу, но как проверка вёрстки агентом, не как артефакт для пользователя.
- Прямого счётчика реплик «а как проверить / собери / запусти» после отчёта нет — оценка по transcript'ам на replay.

## Гипотеза

Если gate обязан приложить артефакт по фиксированному приоритету (web → живой localhost; Android → debug APK под физическое устройство, установка только с согласия; остальное → вывод/снимки/путь) и без артефакта вердикт `NOT READY`, то (а) пользователь подтверждает результат по реальному поведению, а не по диффу, (б) исчезает цикл «отчёт → просьба собрать → второй отчёт», (в) установка на личное устройство никогда не происходит молча — согласие спрашивается `AskUserQuestion` и не переносится между задачами.

## Изменения

- `skills/task-gate/SKILL.md`:
  - новый п. **5.1b Артефакт для подтверждения** — классы по платформе, приоритет, правило согласия на установку, fallback только с доказанной причиной, `❌ no artifact` → `NOT READY`;
  - 5.2: строка 5.1b в таблице, блок `🎁 Artifact:` перед запросом подтверждения, `AskUserQuestion` про установку после отчёта (ответ на него ≠ подтверждение результата), поле `artifact` в `task-gate-timings.jsonl`;
  - 1.1: 5.1b в списке «режим не ослабляет»; Re-entrancy: `artifactServer` в state-файле, повторный прогон гасит и перезапускает dev-server (иначе `200` от старого процесса выдаёт сборку до фикса за артефакт); Step 6 п. 5: остановить фоновый dev-server до `ExitWorktree`; frontmatter и «Связанные скиллы».
- `skills/task-gate/references/artifact-handoff.md` — процедура по платформам (`run`, `assembleDebug` + `adb devices -l`, `/install-device` только после согласия, `curl`/Playwright), что артефактом не считается, формат строк. Согласие привязано к сборке после последней правки: `/install-device` для репро бага на старой сборке — не согласие на сборку с фиксом (находка diff review 2.3b: при конфликте подписи команда делает `uninstall` сама).
- `commands/install-device.md` — ответ на `AskUserQuestion` 5.1b признан явным запуском команды (иначе строка «только при явном запуске пользователя» и 5.1b разрешались бы произвольно).
- `CLAUDE.md` → «Definition of Done»: триггер в одной фразе (переписан абзац, −4 символа: файл на пределе бюджета 37 000 символов).

## Target
