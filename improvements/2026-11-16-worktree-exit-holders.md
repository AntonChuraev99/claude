# Держатели каталога worktree и отложенная уборка

## Цель

Пользователь: «надоело сталкиваться с проблемой удаления дерева после выхода после влития». Нужно, чтобы каталог убирался сам, а причина ловилась автоматически, без ручных команд.

## Baseline (2026-11-16)

Разбор транскриптов всех сессий профиля, где был `ExitWorktree({action: "remove"})`:

| показатель | значение |
|---|---|
| сессий с выходом `remove` | 210 |
| каталог остался («could not remove it — kept at …») | 105 (50%), источник: разбор транскриптов |
| первый вызов отклонён «Worktree has N commits» (squash) | 101 вызов, источник: разбор транскриптов |

Доля сессий, где каталог остался, в зависимости от того, что запускали до выхода:

| в сессии было | каталог остался | без этого |
|---|---|---|
| dev-server (`npm run dev`, `vite`, `wrangler dev`) | 68% | 38%, источник: разбор транскриптов |
| Playwright | 66% | 38%, источник: разбор транскриптов |
| `Monitor` | 8 из 10 | 48%, источник: разбор транскриптов |
| Gradle | 44% | 53%, источник: разбор транскриптов |

`core.fsmonitor` не включён — git-демон исключён (источник: `git config --get core.fsmonitor` вернул пусто). Держатель в базовых 38% не известен: процессы на живом repro не снимались.

Попутно найдено в процедуре Step 6:

- `gh pr merge --squash --auto --delete-branch` как единственная команда GitHub; в логах есть отказ `Auto merge is not allowed for this repository`, после которого PR остался `OPEN BLOCKED`;
- `git branch -d` для worktree, в который вошли по `path`: после squash отказывает всегда, а процедура читала отказ как «merge не состоялся»;
- память о падении `--delete-branch` из worktree (gh 2.88) устарела: на gh 2.102.0 80+ вызовов без этой ошибки.

## Гипотеза

Windows не удаляет каталог, который служит текущим каталогом живого процесса или держит открытый файл. Держатели — процессы, которые сессия сама запустила в worktree и не остановила до выхода: фоновые задачи, `Monitor`, браузер Playwright, процессы субагентов. Это совпадает с отчётами Claude Code на Windows (MCP-серверы, неубитые процессы субагентов, dev-server). Остановка до выхода снимает большую часть случаев. Остаток ловит отложенный уборщик вне сессии, а снимок держателей на каждом случае закрывает пробел в 38% (источник: таблица Baseline выше).

## Изменения

- `hooks/worktree-exit-watch.ps1` (новый, PostToolUse `ExitWorktree`) + `hooks/worktree-exit-watch.tests.ps1` (30 проверок, включая настоящий процесс-держатель и настоящий WMI-запуск):
  - держатели — процессы с текущим каталогом (PEB через `NtQueryInformationProcess` + `ReadProcessMemory`, без прав администратора), исполняемым файлом или командной строкой внутри каталога, плюс держатели открытых файлов через Restart Manager (по файлам, оставшимся в каталоге — тул уже снёс незалоченное; закрывает демоны вроде Gradle, у которых cwd вне worktree); цепочка родителей до сессии и пометка «запущен этой сессией»; вывод `handle64` при наличии;
  - лог `~/.claude/stats/worktree-holders.jsonl` (вне git): `exit` (`removed` / `kept` / `kept_silent`) и `cleanup` (`deleted` / `gone` / `gave_up` / `skipped_*`, `after_sec`);
  - отложенный уборщик через WMI `Win32_Process.Create` (`ShowWindow=0`): вне job-объекта сессии, переживает её выход, окна не открывает; 15 с × до 10 минут; правила безопасности `worktree-shell-sweep`;
  - чужие процессы не убивает — решение за агентом.
- `skills/task-gate/SKILL.md` Step 6: п. 3 — `--auto` по условию; п. 5 — освободить каталог до выхода, `discard_changes: true` сразу после `MERGED`, оставшийся каталог — по сообщению хука, без ручного `rmdir`.
- `skills/task-gate/references/mr-merge.md`: «Merge» — условие для `--auto` (по тексту `gh pr checks --required`, не по коду выхода), `--delete-branch` из worktree безопасен; «Уборка» — три шага (освободить → выйти → хук), `git branch -D` вместо `-d`, таблица действий по сообщению хука, однострочник разбора лога.
- `settings.example.json`: регистрация `worktree-exit-watch` и недостававшего `worktree-shell-sweep`. Живой `~/.claude/settings.json` (gitignored, не проверено — вне git) правится в профиле после merge.

## Target (к 2026-11-30)

- в `stats/worktree-holders.jsonl` у 90%+ (целевое значение, источник: эта запись) строк `kept` поле `strong_holders` ≥ 1 (держатель найден по cwd, exe или открытому файлу, а не только по командной строке) — пробел в 38% назван;
- каталог остался — не более 20% выходов `remove` (было 50%; целевое значение, источник: эта запись);
- из оставшихся 80%+ (целевое значение, источник: эта запись) получают `cleanup: deleted | gone` в той же сессии, без SessionStart-хука;
- первых отказов «Worktree has N commits» после подтверждённого merge — 0.

## Replay

_Не заполнено. План проверки:_

1. Однострочник из `mr-merge.md` → «Уборка», шаг 3: распределение `outcome` и топ держателей.
2. Держатель-лидер не из списка «освободить каталог» → добавить его в шаг 1 или чинить источник.
3. Много `kept` без держателей и `deleted` за 15–30 с → короткий хендл самой сессии; тогда issue в Claude Code, а уборщик остаётся.
