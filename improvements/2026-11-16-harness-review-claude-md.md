# Ревью харнесса 2026-11: CLAUDE.md, improvements, settings

Часть ревью харнесса из четырёх PR (хуки, task-gate, агенты, CLAUDE.md). Здесь — CLAUDE.md, процесс improvements, `CONTRIBUTING.md` и живой `settings.json`.

## Цель

Оставить в CLAUDE.md инварианты и снять обязательность там, где модель делает работу сама или где правило расходится с практикой. Внешняя сверка (2026-11-16): гайды Anthropic по Opus 5.5 и best practices Claude Code — явные шаги проверки и планирования вызывают over-verification; инструкция, которая должна выполняться всегда, принадлежит хуку; McMillan (arXiv 2605.10039, один нерецензированный замер) — на соблюдение влияет длина сессии, а не размер файла правил.

## Baseline (2026-11-16, 30 дней, 454 сессии, 262 ч активной работы)

- Фаза `/task-gate` — 12,8% активного времени, фаза `/commit` + Step 6 — 6,7%.
- Гейты: `full` 526, `lite` 147 — порог «5+ файлов» срабатывает на файлах документов, которые создаёт сам гейт.
- Правки `.md` главным — 8,7% времени генерации главного.
- `@test-expert` вызван 2 раза за 47 дней, хотя по правилу через него шло red-репро каждого багфикса.
- Просроченных replay в индексе improvements — 29; последний пакетный replay — 2026-10-08.
- CLAUDE.md — 139 строк, 17 487 символов (после PR #79) при пороге хука 17 500; `CONTRIBUTING.md` называл порог 37 000 (issue #72).
- Живой `settings.json`: `permissions.allow` — 216 записей при `bypassPermissions`, из них 154 на несуществующие инструменты (mobile — только у `@mobile-tester`, revenuecat — сервера нет, firebase и figma — снятые тулы, включая разрушающие); `skillOverrides` — 39 ключей `amplitude:*`/`revenuecat:*`, которые на плагинные скиллы не действуют.

## Гипотеза

Ритуалы, привязанные к числу файлов и итераций, срабатывают почти всегда и перестают различать задачи. Привязка к файлам кода и к сигналам, которые действительно говорят о риске (неверный план, стоп по fail-loop'ам), вернёт им смысл и снимет время без потери инвариантов.

## Изменения

- `CLAUDE.md`:
  - перечень расширений прод-кода заменён правилом «собирается, исполняется или рендерится» с примерами;
  - § «Цена вызова инструмента»: два пункта в один, границы печатает хук `bash-tool-discipline`;
  - ссылка на скилл `git-commit-conventions` (удаляется в PR task-gate) → формат держит `/commit`;
  - перечень прод-файлов: «собирается или исполняется»; слово «рендерится» не взято — под него попал бы markdown, который главный пишет по `doc-task`;
  - запись improvements — только для правки, которая меняет поведение; replay — только при метрике, пакетом через `/agent-audit`;
  - Prompt Contract шаг 4: полный контракт в чат — при 3+ файлах, новой зависимости, миграции или двояком запросе, иначе одной строкой GOAL (§ «Цена вызова инструмента» требует прозы только от полного контракта); четыре поля по-прежнему определяются на каждой задаче; `@knowledge-scout` пропускается и у проекта без `docs/` и memory;
  - worktree: из проверки «до первой правки» убраны пункты, которые гарантирует `EnterWorktree`;
  - Jira, продукт и маркетинг, вёрстка: детали, которые уже есть в агентах и скиллах, убраны;
  - тесты: red-репро пишет доменный специалист (граница `@test-expert` — в PR агентов);
  - Definition of Done и документирование: «5+ файлов» → «5+ файлов кода»; признак «2+ итерации» заменён на «стоп по 3 fail-loop'ам».
  - Итог: 138 строк, 16 939 символов.
- `CONTRIBUTING.md`: порог 17 500 как в хуке (closes #72); запись improvements — только для смены поведения.
- `improvements/README.md`: `target_date: none` и `replay_status: n/a` для правок без метрики; replay пакетом при 10+ просроченных.
- Живой `settings.json` (вне git, резервная копия рядом): `allow` 216 → 62, удалены 39 мёртвых `skillOverrides`. Пользовательские копии cloudflare-скиллов оставлены: они новее плагинных и ссылаются на `cf-cli` и `gateway-workers`, которых в плагине нет.
