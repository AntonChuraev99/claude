# Вотчдог фонового субагента по росту транскрипта

## Цель

Фоновый `Agent` может зависнуть на старте: `ListAgents` показывает `running · started 1h ago`, уведомление о завершении не приходит никогда, `SendMessage` в очередь ложится и не обрабатывается. Главный ждёт уведомления, которого не будет, и узнаёт о проблеме от пользователя. Нужен наблюдаемый признак жизни и автоматическая реакция.

## Baseline (до изменений, на дату 2026-09-14)

- Сессия `<your-project>` 2026-09-14, `task-gate` full, фан-аут 2.0: два `general-purpose`-ревьюера одним сообщением (Standards на `sonnet`, Spec на сессионной модели), обоим — путь к пакету 363 КБ. Standards вернулся за 5 мин. Spec: транскрипт `tasks/<id>.output` 0 байт с момента спавна, статус «running» 74 минуты, пока пользователь не спросил «что так долго». `TaskStop` отработал, респавн с тем же брифом (на диффе задачи, 186 КБ) начал писать транскрипт сразу.
- Существующий приём для фоновых Bash-задач («прогресс мерить mtime лога, не grep-ом», memory 2026-08-25) на субагентов не переносился — не было ни скрипта, ни шага в гейте.
- `maxTurns` во frontmatter агентов как ограничитель не помог бы: агент не сделал ни одного хода.

## Гипотеза

Первая версия (опровергнута в той же сессии): «0 байт транскрипта = агент завис». Первый же прогон сторожа на респавне дал `STALLED-ZERO` через 121 с, а агент при этом благополучно вернул отчёт; у Standards-оси (тоже `general-purpose`, завершилась за 5 мин) файл тоже 0 байт. **Встроенные типы транскрипт не пишут** — файл не различает живого и зависшего; растёт он только у доменных агентов (`.claude/agents/*.md`: core-expert 2,1 МБ, feature-expert 3,1 МБ).

Рабочая гипотеза: если ревью- и research-бриф несёт бюджет вызовов («≤25, отчёт обязателен, непрочитанное — строкой»), а главный сразу после фан-аута армирует потолок по времени (`CAP` → «заверши сейчас» → `TaskStop`), то зависший или разогнавшийся агент обходится в ≤ 15 мин вместо «пока не спросят». Доменным агентам дополнительно — сторож по росту транскрипта.

## Изменения

- `scripts/agent-watchdog.sh` — новый: `sh agent-watchdog.sh <output_file>...`, одна строка stdout на исход (`STALLED-ZERO` / `STALLED` / `CAP` / `GONE`); `WATCHDOG_ZERO_SEC=0` / `WATCHDOG_STALL_SEC=0` выключают проверки по файлу (режим для встроенных типов — только `CAP`). Запускается через `Bash(run_in_background)`. Smoke-тест: пустой, stale, отсутствующий файл, выключенная zero-проверка — все исходы воспроизведены.
- `skills/task-gate/SKILL.md` §2.0 — новый п. 4 «Бюджет и сторож»: бюджет вызовов в бриф каждой оси, `WATCHDOG_ZERO_SEC=0 WATCHDOG_MAX_SEC=900` на оси 2.3b, дефолты — на L2; реакция на каждый исход; нумерация отсечек времени сдвинута на 5.
- `CLAUDE.md` → «Делегирование», буллет про бриф: «running» не доказывает жизнь, встроенные типы транскрипт не пишут → бюджет вызовов + сторож (дописано в существующую строку, число строк файла не выросло — он на лимите 200).
- `references/claude-md-precedents.md` — прецедент `agent-watchdog` (тег укорочен: `CLAUDE.md` на пределе бюджета 37 000 символов, правка уместилась в существующую строку буллета «Бриф субагента»).

## Target

К 2026-09-28: в каждом брифе осей 2.3b есть строка бюджета; на каждом `task-gate` full с фан-аутом в transcript'е есть запуск `agent-watchdog.sh`; ни одного ожидания субагента дольше 15 мин без стоп-сигнала; реплик «что так долго» — 0.
