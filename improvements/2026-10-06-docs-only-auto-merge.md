# Auto-merge для диффа только из документации

## Цель

Правка документации не меняет поведение, но `/task-gate` останавливается на отчёте и ждёт подтверждения так же, как для кода. Пользователь тратит реплику на «да» без содержательной проверки. Нужно: агент сам доделывает, проверяет и вливает такие правки.

## Baseline (до изменений, на дату 2026-10-06)

- Step 6 запускается только после подтверждения пользователя, исключений нет (`skills/task-gate/SKILL.md` Step 6, `references/mr-merge.md` гард 6).
- Доля docs-only задач среди прогонов gate — не замерена; на replay посчитать по `git log` проектов коммиты `docs:` с PR.

## Гипотеза

Детерминированный критерий по путям файлов (allowlist `docs/**`, корневые `*.md`, `improvements/**` в харнессе; denylist инструкций агентов и `.md` в сборке продукта; без деплоя на транке) отделяет правки без влияния на работу. Оценка «влияет ли» по смыслу не нужна — она и есть место ошибки.

## Изменения

- `skills/task-gate/references/mr-merge.md` — раздел «Без подтверждения: дифф только из документации» с полным условием; гард 6 принимает исключение.
- `skills/task-gate/SKILL.md` — Step 6, вступление и «Что скилл НЕ делает» ссылаются на исключение.
- `CLAUDE.md` § «Git-коммиты» — фраза про исключение в существующей строке; число строк не выросло, символов +~100 (файл и до правки выше лимита 37 000).
- `skills/harness-contributing/SKILL.md` — шаг 5 ссылается на исключение.
- Критерий закрывает дыры, найденные ревью: файл `docs/`, импортированный в `CLAUDE.md` через `@`, — инструкция; сайт документации без CI-файла (GitHub Pages from branch, mkdocs, Read the Docs) — деплой.

Комментарии в коде под исключение сознательно не включены: класс файла «код», отсутствие влияния не доказывается путём.

## Target

К 2026-10-20: ни одна docs-only задача не остановлена на подтверждении; ноль откатов auto-merge.
