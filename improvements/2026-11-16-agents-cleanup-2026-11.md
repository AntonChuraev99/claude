# Чистка определений субагентов (ревью харнесса, трек C)

## Цель

Набор агентов висит в каждой сессии главного суммой `description` и решает маршрутизацию. Аудит за 47 дней показал агентов без вызовов, границы, которые не исполняются, и тела над бюджетом. Задача — меньше резидентного текста при тех же триггерах, у каждой зоны один владелец, ни одного мёртвого адресата.

## Baseline (до изменений, на дату 2026-11-16)

Вызовы за 47 дней (2026-09-30…11-16): android-platform 37, best-practices-scout 68, bug-pattern-reviewer 0, compose 48, core 18, design 61, feature 63, google-play 44, jira 47, **kmp 0**, knowledge-scout 64, marketing 15, mobile-tester 15, nextjs 42, product 50, react-ui 100, **test-expert 2**, video 1, **wasmjs 0**.

- Сумма `description` 19 агентов — 25 335 символов (замер скриптом после PR #79; до него аудит дал 25 228). Выше 1 500: marketing 1 950, product 1 734, google-play 1 637, test 1 566, core 1 529.
- Формула «тесты по закрытому списку @test-expert — багфикс-репро, mutation matrix…» — в 4 description и 2 короткие формы; закрытый список test-expert не исполнялся (2 вызова).
- Все 19 frontmatter не проходили `yaml.safe_load`: `: ` внутри неэкранированного `description` (рантайм Claude Code разбирает их снисходительно).
- Тело design-expert 13 776 символов (блокер > 13 000); блока «Цена инструмента» нет у design, product, marketing, google-play.
- design-expert делал `claude-design` методом по умолчанию и требовал `ToolSearch(select:DesignSync)` — субагенту тул недоступен.
- Индексы памяти выше лимита загрузки ~25 KB: compose-expert 32 306 B, test-expert 26 722 B (с сырым NUL внутри), react-ui-expert 25 997 B; android-platform-expert 22 660 B.
- Утечки в публичный репо в 5 агентах: имя приложения в справочнике nextjs-expert, проектные пути харнессов, имена констант, классов навигации, модулей и компонентов дизайн-системы, внутренняя статистика задач.
- Мёртвые адресаты: `vercel:*` в nextjs-expert и react-ui-expert (плагин удалён).

## Гипотеза

1. KMP-архитектура и сборка KMP — одна зона: раздельные агенты давали 0 вызовов kmp-expert и лишний контрактный хоп. Слияние в android-platform-expert убирает хоп без потери инвариантов.
2. Red-репро багфикса пишет тот, кто чинит: он уже держит контекст корня. Test-expert остаётся для SPEC, недостающей тест-инфраструктуры, чужого и legacy-кода, mutation matrix по запросу и неопределённого контракта.
3. Скриншот-инфраструктура у владельца стека (Android → android-platform-expert, web visual → react-ui-expert) снимает трёхстороннюю неопределённость compose / test / platform.
4. Короткая единая DO NOT-формула и чистка description снижают резидентный бюджет без потери триггеров.
