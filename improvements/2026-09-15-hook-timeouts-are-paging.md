# Таймауты хуков — симптом подкачки, не хуков

## Цель

Сообщение `UserPromptSubmit hook timed out after 10s — output discarded` вернулось «часто». Разобрать по факту, а не поднимать `timeout`, и убрать из хук-слоя то, что стоит спавна, но не даёт данных.

## Baseline (до изменений, на дату 2026-09-15)

Источник — транскрипты сессий: CLI 2.1.272 пишет в них `attachment.type = hook_cancelled` с `durationMs`, `timeoutMs`, `timedOut`, `command`. Первый прогон `scripts/hook-timeouts-report.py --days 45`:

- **281 таймаут за 45 дней (сессии + транскрипты субагентов, снимок на 2026-09-15 ~13:30), 14 разных хуков.** Топ: подсказка плагина ast-index на `Grep` (121+, лимит 5 с, медиана факта 10.5 с, максимум 308 с) · уведомление Warp на промпт (49, лимит 10 с, медиана 20.2 с, максимум **89 с**) · `branch guard` pwsh (28) · Warp на Stop (18) · трекер caveman (17) · `stop-gate.ps1` (16) · собственный `incident-logger.js` (3, при внутренней работе 5 мс — снаружи 10–14 с).
- По дням: 0 в тихие дни, 58 / 44 / 40 / 32 в загруженные при 100–800 человеческих промптах в день. 24 «пачки» — таймауты в одном 2-секундном окне (от первого в группе) у 2–3 сессий разных проектов: стоит вся машина, таймер убийства в самом CLI срабатывает с опозданием в разы.
- Windows Resource-Exhaustion-Detector (System log, id 2004): три записи 11.09 и две 17–18.08 — «нехватка виртуальной памяти», топ — JVM-демоны + эмулятор / игры.
- На момент замера: RAM 15.6 ГБ, свободно 0.4 ГБ, commit 34 ГБ. Kotlin-демон-сирота с мёртвым родителем держал 4.4 ГБ.
- `error-logs/incidents/` за всю жизнь `incident-logger.js` — **пусто**: логгер мерил время внутри node (p50 5 мс, max 184 мс), а стойка — до старта процесса. Детектор был слеп ровно к тому, ради чего написан.
- `session-docs-digest.py` в проекте с 51 файлом в `docs/active` отдавал additionalContext 12–21 КБ; CLI заменял его на `<persisted-output> Output too large` — **131 сессия за 30 дней без дайджеста**, ещё 13 в соседнем проекте. Граница инлайна нечёткая: 12.3 КБ уже persist, 16.8 КБ ещё инлайн.

## Гипотеза

Поднимать таймауты бесполезно: стойки длятся 10–89 с, а хуки-жертвы уведомительные. Единственный рычаг в `~/.claude` — меньше спавнов на промпт. Хук, который не даёт данных, — чистая цена: его снятие уменьшает число процессов на промпт с 3 до 2, а данные о таймаутах берутся из транскриптов, где они уже лежат точнее. Дайджест с потолком по символам дойдёт до модели в любом проекте.

## Изменения

- `settings.json` (приватный, вне репозитория): секция `UserPromptSubmit` с `incident-logger.js` снята в живой копии до вливания ветки — иначе после `git pull` хук звал бы удалённый файл на каждом промпте. `settings.example.json` её и не содержал.
- `hooks/incident-logger.js` — удалён. `hooks/log-incident.js` (ручной лог) оставлен.
- `scripts/hook-timeouts-report.py` — новый: таймауты по командам, по дням (рядом с числом промптов — только человеческих: без `toolUseResult` и без `isMeta`-тел скиллов), пачки (машинная стойка, окно от первого в группе), таймлайн, non-blocking-ошибки хуков — из транскриптов сессий и субагентов под `<config dir>/projects/`. Тесты — `scripts/hook-timeouts-report.tests.py`, две мутации (фильтр `isMeta`, цепочное окно пачек) падают на предсказанных assert'ах.
- `hooks/session-docs-digest.py` — additionalContext ограничен `CLAUDE_DIGEST_CONTEXT_BYTES` (по умолчанию 8 000 байт UTF-8: порог CLI меряется размером, а кириллица — два байта на букву): горячие триггеры todos первыми и полностью, дальше каждая запись получает одну строку с путём, остаток бюджета уходит на три строки для самых свежих, не влезшее — счётчиком по секции. Два теста в `session-docs-digest.tests.py`, доказаны тремя мутациями (потолок 100 000 → «context within default budget»; без приоритета горячих → «hot todo kept in full form»; без апгрейда до полной формы → «newest entry keeps its full form»).
- `error-logs/README.md` (приватный): источник истины — транскрипты и отчёт, класс «UserPromptSubmit timeout» переписан на подкачку.

Вне `~/.claude`, не делалось, зафиксировано в отчёте пользователю: относительный путь хука проекта `.claude/hooks/detekt-format.ps1` (143 ошибки из сессий, стартовавших в подкаталоге; лечится `$CLAUDE_PROJECT_DIR`), 51 файл в `docs/active` проекта, два Kotlin-демона из-за двух версий Kotlin (см. `docs/backlog/gradle-daemon-sprawl.md`).

## Target

К 2026-09-29 по `scripts/hook-timeouts-report.py --days 14`:

- `incident-logger.js` в таблице отсутствует (0 против 3); число процессов на UserPromptSubmit — 2.
- SessionStart-дайджест ни разу не ушёл в `<persisted-output>` (проверка — в отчёте по транскриптам строка `Дайджест доков` присутствует у `hook_additional_context`, `persisted-output` — нет).
- Общее число таймаутов в день — не метрика этой правки: оно задаётся памятью машины. Если оно не падает при свободной RAM > 2 ГБ — гипотеза о подкачке неверна, копать хуки.
