# Claude Code System Improvements

Лог изменений конфигурации, агентов и правил — и их влияния на метрики.

## Зачем

Каждое изменение глобальных правил (`CLAUDE.md`, агенты, скиллы, хуки) — гипотеза. Без записи baseline и target **до** правки и replay-аудита через N дней невозможно понять, что сработало, а что нет: остаётся впечатление «вроде стало лучше», которым нельзя ни воспользоваться, ни поспорить.

Этот каталог — журнал таких гипотез.

## Структура файла улучшения

`<YYYY-MM-DD>-<slug>.md` — один файл на одно изменение или на группу изменений, объединённых общей целью.

```markdown
---
date: YYYY-MM-DD
slug: <slug>
status: applied | reverted | partially-applied
goal: <одна строка>
metric: <что меряем — hit rate / cost per task / итерации>
baseline_date: YYYY-MM-DD
target_date: YYYY-MM-DD  # когда replay-аудит
---

# <Название>

## Цель
<что хотим улучшить и почему>

## Baseline (до изменений, на дату <date>)
<метрики на момент перед применением; числа есть — числа, нет — честно «нечем измерить» и чем это лечится>

## Гипотеза
<почему думаем, что это поможет>

## Изменения
<какие файлы как изменены, со ссылками на конкретные правки>

## Target
<какой результат ожидаем после <target_date>>

## Replay (заполняется через N дней)
<реальные метрики после внедрения, выводы>
```

## Как использовать

1. Перед применением правки — создать файл, заполнить всё **до** Replay.
2. Применить правки в указанные файлы.
3. Через 7–14 дней (или после накопления N задач) — запустить `/agent-audit` и заполнить **Replay**.
4. Гипотеза не подтвердилась → `status: reverted`, откатить.
5. Подтвердилась → `status: applied`, оставить и зафиксировать как практику.

## Публикация и анти-утечка

Каталог публикуется вместе с репозиторием, чтобы улучшение ехало в MR рядом с правкой, которую оно объясняет. Отсюда требование к каждой новой записи — **писать её санитизированной с первой строки** (`CLAUDE.md` → «Публичный репозиторий»):

- имена проектов и приложений → `<your-project>`, `com.example.*`;
- пути с username → `~/...` или `YOUR_USERNAME`;
- API-ключи, токены, числовые project ID → плейсхолдер или gitignored `config/*.local.md`.

Прецедент ценен датой, механизмом и цифрой — не именем проекта, в котором случился. Anti-leak pre-commit хук — страховка, а не замена правилу: сработал → почистить и пере-добавить, не обходить `--no-verify`.

**Записи эпохи приватного каталога (195 штук) лежат в `archive/` и остаются приватными.** Граница — происхождение записи, а не дата: они писались до перехода на публикацию, когда обобщать имена было незачем, и половина называет реальные проекты, числовые ID и личные пути. Запись, написанная до перехода, остаётся в архиве, даже если датирована самим днём перехода. Их индекс — `archive/INDEX.md`, тоже приватный (его нет в опубликованном дереве — это ожидаемо). Переносить оттуда запись в публичную часть можно только после чистки.

Правила ссылаются на архивные записи путями вида `improvements/archive/<дата>-<slug>.md`. Такой путь в опубликованном дереве не разрешается — он адресует приватный файл; подробнее — [`ARCHIVE.md`](ARCHIVE.md).
