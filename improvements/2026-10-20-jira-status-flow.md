# Статус Jira-задачи по ходу работы

## Цель
Пользователь переводит статусы руками: «в работе» на старте, «готово к сборке» после merge, «готово к тесту» после сборки для тестировщика. Агент знает все три момента, но переводы запрещены без явного запроса (прецедент 2026-07-24: автоперевод свежесозданных задач).

## Baseline (до изменений, на дату 2026-10-20)
Переводов по событиям нет: 0 из 3 на каждую задачу. Счётчика нет, считается по брифам `EVENT:` к `@jira-expert` в транскриптах.

## Гипотеза
Событие в брифе (`EVENT: start | merged | tester-build`) — явный запрос с фиксированным целевым статусом. Запрет на автоперевод созданных задач остаётся: он про догадку о статусе, а не про событие.

## Изменения
- `CLAUDE.md` → «Статус Jira-задачи»: триггер на три события; ключ — в slug worktree и заголовке MR (squash кладёт заголовок MR в транк, по нему `tester-build` находит ключи).
- `agents/jira-expert.md` → «Статус по ходу работы»: таблица событие → статус → допустимый текущий статус, правило «только ключи из коммитов сборки», шаблон брифа для главного.
- `skills/task-gate/SKILL.md` Step 6 п. 6 и `references/mr-merge.md` → «Отчёт»: перевод после подтверждённого merge, строка `Jira:` в отчёте.
- Приватно: `config/jira.local.md` § «Жизненный цикл» (имена и id статусов проекта), конвенции агента — исключение для `EVENT:`.

«Сборка для теста» — только по просьбе «подними версию и собери debug APK». Обычная сборка и `/install-device` статус не меняют (решение пользователя).

## Target
К 2026-11-03: каждая задача по ключу получила три перевода; ни одного перевода назад по потоку и ни одной задачи в «готово к тесту», которой нет в APK.
