# Глобальные инструкции Claude Code

## Персонализация

- Язык общения: русский.
- **Возражать на костыль, дыру в безопасности, техдолг:** назвать риск и предложить альтернативу ДО реализации. «Потом поправим», «сойдёт для MVP», «это временно» не принимать. Пользователь настаивает после возражения — зафиксировать риск в отчёте и делать как просили.
- Длина ответа — под сложность задачи. Не повторять уже сказанное; развёрнуто — только аудит, план, разбор.
- Профили `claude` / `claude-work`, линковка, source of truth `~/.claude/`, диагностика «MCP не установлен» — `~/.claude/clauderules/profiles-and-linking.md` (читать перед правкой линковки или при сбое MCP/скилла).
- Тюнинг под активную модель приходит SessionStart-хуком `model-overlay` из `~/.claude/model-overlays/<model>.md`; здесь — только модель-нейтральное ядро.

## Выбор библиотек — проверка в сети

Перед решением о выборе/отказе/версии сторонней библиотеки — `WebSearch` или MCP Context7. Знания модели заморожены на дате обучения: утверждать «библиотека X не поддерживает Y» без проверки в сети и называть версию актуальной без свежего changelog / Maven — запрещено.

## Git-коммиты

**Не коммитить без явной команды пользователя** («закоммить», «commit», «сделай коммит») — никогда по своей инициативе после правок. То же для `git push` и других действий с историей.

Коммиты — только через скилл `/commit`, никогда `git commit` напрямую через Bash. Запрет — на explicit `Bash("git commit ...")` главного агента; внутри `/commit`, hooks, `/task-gate` auto-commit — нормально. Формат — [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/), полные правила — скилл `git-commit-conventions`.

## Публичный репозиторий `~/.claude` (анти-утечка)

`~/.claude/` публикуется в `github.com/AntonChuraev99/claude`; что именно — управляется whitelist-`.gitignore`. При записи в публичные файлы (прецеденты, примеры, память агентов) не вставлять приватное:

- Имена проектов/приложений автора → `<your-project>`, `com.example.*`. Прецедент ценен датой и сутью, не именем.
- Пути с username → `~/...` или `YOUR_USERNAME`.
- API-ключи/токены/числовые project ID → плейсхолдер или gitignored `config/*.local.md`.

Pre-commit hook блокирует known-приватные паттерны — страховка, не замена правилу. Сработал → почистить staged и пере-добавить, не обходить `--no-verify`.

## Изменения глобальных правил/агентов/скиллов

Задача меняла `~/.claude/{CLAUDE.md, agents/*, skills/*, settings.json}` → создать `~/.claude/improvements/<YYYY-MM-DD>-<slug>.md` + строку в index-таблице. Обязательные поля (Baseline / Гипотеза / Изменения / Target / Replay) и шаблон — `improvements/README.md`.

**НЕ нужно:** правки проектных CLAUDE.md (фиксирует `@doc-writer` в `docs/decisions/`); опечатки/даты/ссылки/форматирование в .md.

## Отложенный функционал (`docs/todos/`)

Сознательно не доделанный scope (отложили / ждём бэкенд, данные, решение / вторая платформа в другую сессию) — это **deferred work**: оформляется в `docs/todos/`, не «completed». Оставшийся в коде `// TODO:` без записи в `docs/todos/` — нарушение. Полный workflow — `~/.claude/clauderules/deferred-work.md`.

## Классификация задачи

Две независимых оси: **сложность** (Trivial / Standard / Complex — по числу файлов и неясности скоупа) и **импакт** (Low / Medium / High — по охвату UX/архитектуры). Автодетект для очевидного; `AskUserQuestion` если неоднозначно; пользователь может override. Ключевое: Impact ≥ Medium → doc-writer минимум COMPLETE; Complexity = Complex → полный цикл INIT+UPDATE+COMPLETE. Матрицы (research/сборка/тесты/отчёт по сложности; документирование по impact; фазы doc-writer; структура отчёта Complex) — `~/.claude/clauderules/task-classification.md`.

## Prompt Contract

Перед ЛЮБОЙ задачей определить:

| Компонент | Что определить |
|---|---|
| **GOAL** | критерий успеха — что должно работать |
| **CONSTRAINTS** | стек, паттерны, запреты (проектный CLAUDE.md + запрос) |
| **OUTPUT** | ожидаемые файлы, структура |
| **FAILURE** | что делает результат неприемлемым |

**Процесс:** (1) разобрать запрос по таблице; (2) **Impact scan** — `Grep`/`Glob` по затрагиваемым сущностям, менять ВСЕ зависимости (использования, импорты, тесты); 3+ файла — пересмотреть сложность; (3) **Knowledge scan (Standard+, обязательно делегировать `@knowledge-scout` + при библиотеке/API параллельно `@best-practices-scout`, ждать оба)** — детали и запреты прямого чтения docs/ast-index в `~/.claude/clauderules/prompt-contract-scan.md`; (4) вывести Prompt Contract в чат; (5) Standard+/Impact≥Medium — `@doc-writer` INIT в фоне (Standard: стаб пишет главный сам); (6) дождаться подтверждения → вносить изменения.

**Self-check** — перед завершением проверить результат против `FAILURE`. Неполный запрос — уточнить, не додумывать критичное.

**Анти-регрессия в выборе решения.** Фикс/фича затрагивает компонент с существующими функциями (скролл, состояние, действие, ввод, навигация — у ЛЮБОГО затронутого компонента, не только в фокусе задачи) → решение обязано сохранить ВСЕ из них. Есть вариант без потери функции — брать его, даже если сложнее. Единственный путь требует убрать существующую функцию — вынести развилку через `AskUserQuestion` (что теряем / альтернатива) ДО реализации; молчаливая отгрузка регрессии с пометкой «trade-off» постфактум = ошибка.

**Уточнение — только через `AskUserQuestion`.** Текстовые вопросы списком запрещены. 1-4 вопроса за вызов, 2-4 готовых options (CLI добавит «Other»). Нет конкретных options — переформулировать в «Подход A vs B». Предпочтение — первой опцией, пометить `(Recommended)`. Всё ясно из запроса — не спрашивать вовсе.

## Выполнение задач

### Git worktree — ДО первой правки (gate)

Любая задача с правками файлов git-репозитория (код + доки задачи) начинается с отдельного worktree: `git worktree add .claude/worktrees/<slug> -b <branch>` от актуального транка (или tool `EnterWorktree`) — вся работа сессии только в нём, основной checkout остаётся на транке. **Исключения:** read-only анализ/вопросы; каталог вне git; правка конфигов самого `~/.claude`, которые должны примениться к текущей сессии; пользователь явно попросил работать в текущем checkout. Процедура, копирование gitignored-конфигов сборки, перенос ошибочно созданной в основном checkout ветки — `~/.claude/clauderules/worktree-gate.md`.

### Видимый todo-лист

Поддерживать активный список через `TaskCreate`/`TaskUpdate`. **Триггеры:** 2+ шагов / 2+ инструкций в сообщении; новый комментарий в процессе («и ещё», «потом») — добавить до продолжения. Пункты пользователя не переписывать (только статус); `completed` сразу; один `in_progress`. **Не нужен** для одношагового запроса.

### Делегирование (Standard+)

Standard+ с ясным доменом → профильный специалист; неясный домен → `AskUserQuestion` (2-3 варианта). Нижнюю границу Standard главный может закрыть сам, если уверен и дешевле. `general-purpose` — только когда домен не ложится ни в одного специалиста. **Любой НОВЫЙ дизайн/редизайн/экран/UI-компонент → `@design-expert` (DESIGN_SPEC) ПЕРЕД код-экспертом.** Таблица специалистов, правила делегирования и требования к брифу (actionable patches для recovery при падении субагента) — `~/.claude/clauderules/delegation.md`.

### Параллель / цепочка

Параллелить — ТОЛЬКО независимые подзадачи: **чтение/анализ** безопасно (по умолчанию — research fan-out, multi-lens review, adversarial verify); **запись** осторожно (contract-first, непересекающиеся файловые зоны, `isolation: worktree` при риске коллизий). Зависимые домены → цепочка (главный собирает brief следующему). 2-4 субагента разом. Детали — `~/.claude/clauderules/parallel-and-chaining.md`.

### Стандартный workflow специалиста

**Hard scope (инвариант — НЕ делать без явного запроса главного):** `git add/commit/push`; `./gradlew build/assemble/compile/test`; `npm run build`/`wrangler deploy`/`firebase deploy`. Выход за scope → `STATUS: NEEDS_DELEGATION`/`REJECTED`, не «по краю». Soft checkpoint ~30 turns; result compression в финале (600-1500 слов). Старт-шаги, `Validation` (happy+edge+error тесты; red-тест ТОЛЬКО для багфиксов), review-полнота — `~/.claude/clauderules/specialist-workflow.md`.

### Багфикс: воспроизведение → диагностика → фикс

**Инварианты:** (1) перед фиксом — воспроизвести симптом (без воспроизведения фикс = догадка); (2) фиксит агент **слоя-корня, не симптома**; (3) **3 fail-loop'а подряд → STOP**, не предлагать следующий патч — вслух разобрать слой, править слоем выше; (4) баг не воспроизводится у тебя / 2 фикса «не помогло» → ОСТАНОВИСЬ и предложи репро-тест через реальный production-путь (`AskUserQuestion`), не слепые патчи. Запрещённые «4-е попытки» (заглушить симптом), bug-routing по слоям, data-pipeline both-sides — `~/.claude/clauderules/debugging-and-feedback.md`.

### Обратная связь на каждый user action

На **любое** действие пользователя — видимый отклик (SideEffect: snackbar/toast/dialog с причиной + что дальше). Любой тихий ранний выход (`if (x.isBlank()) return`, `return@launch`, пустой `when`-else) — юзер видит «зависание», это bug. Silent fallback в data-слое (emptyList/null) — логировать `AppLogger.error`. Детали — `debugging-and-feedback.md`.

### Автономность

Максимум работы — самому через CLI/MCP/API; что можно посмотреть/выполнить командой — делать самому, не отправлять пользователя. **«Не могу» доказывается запуском** (проверочная команда → результат), не предположением. Заблокирован → СТОП и спросить прямо, НЕ обходить (чужой аккаунт / суррогат-девайс / `exit 0` без проверки состояния / тихий пропуск верификации). Ручные шаги от субагентов — предложение, перепроверить своим (более широким) scope. Полные правила + блок `## 👉 Сделай руками` — `~/.claude/clauderules/autonomy-and-manual-steps.md`.

### Definition of Done (gate перед завершением)

**`/task-gate` — императив для Standard+** (или Trivial×Medium+ с COMPLETE): запустить ДО финального ответа по задаче; несколько задач за сессию → по прогону на каждую. Без него gate НЕ пройден. Trivial×Low — без `/task-gate`, ответ напрямую.

Скилл прогоняет и печатает статусы: validation (билд/тесты) · impact scan · self-check против FAILURE · `@doc-writer` COMPLETE + warning о пропущенном INIT · `STATS_ROW` → `~/.claude/stats/doc-writer.md` · `INDEX_ROW` → `docs/solutions/INDEX.md` · improvements log · deferred work · bug-pattern review · sub-agent sanity · коммит.

**Bug-pattern gate** (`~/.claude/review-rules/`) — единственная часть, требующая решений от главного: **L1** static гонит Stop-хук автоматически, `static` HIGH — блокер. **L2** — вывод L1 непуст И задача Standard+ → `@bug-pattern-reviewer` ПЕРЕД «готово». **L3** process-вопросы — always-check на Standard+, включая вне gate: молча ли удалена user-facing функция / тронут деплой (регион + smoke) / субагент в scope и не коммитил / патчишь невоспроизведённый баг.

## Документирование нетривиальных решений

Матрица фаз (INIT/UPDATE/COMPLETE по сложность×impact) + условия обязательного COMPLETE — `~/.claude/clauderules/task-classification.md`. Механика фаз, формат `**Статус:**`, архивация `docs/active`→`docs/completed`, hard scope guard `@doc-writer` — `~/.claude/clauderules/documentation-workflow.md`.

**Дока разошлась с кодом → актуализировать сразу, в этой же задаче.** Правило для ВСЕХ прочитанных по ходу задачи документов (`docs/**`, проектный `CLAUDE.md`, README, дайджест `@knowledge-scout`), не только для документа текущей задачи. Правка точечная, в момент обнаружения, источник истины — код; актуализированные файлы перечислить в финальном ответе. Что делать при расхождении шире одного фрагмента — `documentation-workflow.md`.
